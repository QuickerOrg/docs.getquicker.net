# 从 V1 迁移到 V2

Quicker V2 目前是 Preview，官方 V2 页面标注为「仅专业版」；免费账号数据迁移仍在进行，当前不能登录 2.0。不要把 V2 当作关键 1.x 环境的直接替换，迁移前先读 [体验前必读](/important-notice)。

Quicker 1.x 与 V2 不建议同时安装使用。两代客户端的浏览器扩展等组件会互相冲突；回退的做法是重新安装 1.x，而不是让两代程序同时维护同一套数据。

## 迁移清单

### 1. 在 1.x 中完成同步、导出和备份

1. 在最后使用的 1.x 客户端执行一次同步。
2. 导出特别重要、难以重建或需要审计的动作。
3. 备份关键动作页、公共子程序和本机依赖说明。
4. 记录依赖第三方软件、浏览器扩展、脚本运行环境、文件路径、Office/COM 组件或本机数据库的动作。

不要在没有备份时直接覆盖唯一可用的正式动作。

### 2. 卸载 Quicker 1.x

V2 官方页面提示两代程序不应同时安装。迁移体验前先卸载 1.x，避免浏览器扩展、启动入口和本机组件互相冲突。

如果需要保留 1.x 的可恢复能力，保留安装包、导出文件和数据备份即可，不要让 1.x 与 V2 同时作为日常编辑端。

### 3. 从 V2 官方页面安装

打开 [https://getquicker.net/V2](https://getquicker.net/V2) 下载 V2 安装包。不要从 [https://getquicker.net/Download](https://getquicker.net/Download) 下载 1.x 安装包来体验 V2。

安装前确认当前 Windows 版本受 .NET 10 支持，并且系统为 64 位。若安装包提示缺少运行环境，请按提示安装 .NET 10 Desktop Runtime。

### 4. 首次登录会建立 V2 数据分支

首次登录或初始化时，V2 会迁移或拉取当前账号的 V2 数据，并建立新的本机数据空间。它不是 1.x 数据库的持续双向镜像；之后在 1.x 中继续修改，不应假定会自动进入 V2。

背景说明见 [数据存储与同步变化](/v2/what's-new/data-and-sync#data-fork)。

### 5. 验证动作、触发规则和公共子程序

建议按风险从低到高验证：

1. 先运行不修改外部数据的简单动作，确认变量、表达式和基本步骤。
2. 再验证常用动作页、场景、动作快捷键、轮盘、手势、文本指令和选中文本工具条。
3. 检查公共子程序、子程序调用、多线程、循环、等待和长时间运行的动作。
4. 最后验证文件写入、网络请求、软件控制、Office/COM、数据库驱动和 DLL 等会影响外部状态的模块。

组合动作多数模块会保留兼容运行能力，但需要继续维护的旧版组合动作应迁移为新版组合动作。可以通过 [模块参考](/v2/xaction/modules)核对当前模块定义。

### 6. 回退时重新安装 1.x

需要回到 1.x 应急使用时，重新安装 1.x，并使用迁移前备份或 1.x 自己的数据。不要把 V2 数据目录覆盖到 1.x，也不要用旧版客户端覆盖 V2 数据目录。

如果已经在 V2 中使用新功能，回退前还要阅读 [体验前必读](/important-notice) 中的版本降级风险。

## 需要重点检查的变化

- 动作存储和使用位置分离，删除动作本体与从面板移除位置的影响不同；
- 启用 QkEval 后，不再回退到旧表达式引擎；
- 旧版只读动作不支持会暴露内部结构的断点和单步调试；
- 外部组件不响应取消时，并行分支可能不能立即结束；
- .NET 10、64 位进程和第三方程序集兼容性需要单独检查。

详细背景见 [动作存储、执行与调试](/v2/what's-new/actions)、[组合动作执行与调试变化](/v2/what's-new/actions/xaction-steps) 和 [运行平台与兼容性](/v2/what's-new/platform-and-compatibility)。
