# AI 交互对话

打开流式 AI 对话窗口，在动作运行期间继续追问，并由用户明确选择是否采用当前回答。

使用前，请先在 Quicker 的 **设置 → AI** 中配置服务、模型和文本任务场景。配置方式见[统一 AI 服务与模型设置](/v2/what's-new/ai-services-and-models)。

## 新建会话

1. 将“会话方式”设为“新建会话”。
2. 填写初始问题；如需固定角色或回答规则，再填写完整系统提示词。
3. 运行时在窗口中查看流式回答，并按需继续追问。
4. 点击“采用当前回答”，把最后一条完整回答写入“采用的回答”。关闭或取消窗口会按用户取消结束。

“最大对话轮数”包含首次回答。达到上限后不能继续发送问题，只能采用当前回答或取消。

## 继续已有会话

将“会话方式”设为“继续指定会话”，并传入此前输出的“会话 ID”。指定会话必须存在于当前设备；不存在时步骤会明确失败，不会自动创建空会话。继续会话时沿用原会话的系统提示词，本步骤填写的系统提示词不生效。

每轮追问都会按当前 AI 设置重新解析可用模型，因此调整候选顺序、停用服务或修改凭据后，后续轮次可能使用不同模型。

## 输出与存储

- “采用的回答”是用户点击采用时最后一条完整 Assistant 文本。
- “完整消息历史 JSON”包含本地保存的版本化消息历史，推理内容与回答文本分开记录。
- “调用标识列表 JSON”可用于关联本次交互中的多轮请求。

会话保存在本机，动作分享不会携带会话 ID 对应的历史记录，也不会同步 API Key。跨设备运行时应新建会话，或由动作自行传递所需上下文。

## 注意事项

- 本模块必须显示交互窗口，不适合无人值守或后台执行。只需一次自动处理时，使用 [AI 文本处理](/v2/xaction/modules/ai-text) 的“直接返回”模式。
- 关闭或取消窗口不会输出尚未采用的回答。需要区分取消和请求失败时，请结合步骤结果与“遇到错误时停止动作”设置处理。
- 对话内容会发送给每轮实际选中的 AI 服务商；本地历史也可能包含敏感信息，请按数据要求决定是否使用持续会话。
