# 动作快捷键

动作快捷键把系统级组合键直接绑定到一个 Quicker 动作或操作。它不同于「功能快捷键」：功能快捷键控制显示面板、搜索等 Quicker 内置功能，动作快捷键执行用户配置的内容。

同一个组合键可以在不同场景执行不同内容。例如让 `Ctrl+Alt+S` 在全局运行搜索，在浏览器中保存网页，在图片编辑器中运行导出。

## 快速开始

1. 打开 **场景与动作管理 → 键盘触发 → 动作快捷键**。
2. 左侧选择要设置的场景：全局、普通程序、路径 / 标题 / 窗口类子场景、浏览器或网址。
3. 新增一条规则，录下组合键，并选择要执行的动作或操作。
4. 保存后，切到目标程序按下该组合键。
5. 没有响应时，先在管理页点击 **刷新状态**，再检查是否与其它程序或 Quicker 功能快捷键冲突（**设置 → 快捷键查询 → 快捷键占用查询**）。

规则归属于场景本身，不需要为每条普通场景规则重复填写进程名。原有全局规则仍保留进程白名单和黑名单，方便兼容旧配置；普通场景的编辑器会隐藏这些字段，以免与场景作用域重复。

## 按场景覆盖与禁用

运行时按最具体场景到全局的顺序查找当前快捷键。当前层只要存在相同快捷键的本地规则，就取得这个快捷键的控制权：

| 操作 | 效果 |
| --- | --- |
| 本地规则启用 | 使用本地规则 |
| 本地同键规则全部停用 | 不触发，也不回退上级 |
| 当前层没有定义该键 | 继续查找父场景或全局规则 |
| 删除当前层最后一条同键规则 | 恢复上级继承 |

这和 [按键双击](/v2/features/triggers/key-double-click) 不同：动作快捷键停用本地同键规则会屏蔽上级，不会继续尝试继承规则。要恢复继承，应删除本地同键规则，而不是只停用。

如果同一层为一个快捷键配置了多条动作，会继续使用动作选择菜单，不会强制合并或丢弃已有规则。

管理页默认只显示本场景规则。勾选「显示继承的规则」后，可以查看规则的真实来源，并将继承规则复制到本场景再修改。

常见继承顺序：

- 普通程序：当前程序 → 全局
- 浏览器网址：当前网址 → 当前浏览器 → 浏览器通用场景 → 全局
- 桌面、任务栏和普通资源管理器是不同逻辑场景，建议分别检查

## 前台切换时如何注册

Quicker 只为当前前台场景维护需要的系统快捷键，并按差异增加或释放按键，减少无关快捷键被长期占用。

前台窗口变化时，新旧场景共同使用的按键会尽量保持注册不动；新增按键先注册，旧场景独有按键再释放。

收到快捷键消息后，还会重新核对当前窗口、网址和最新规则，而不是直接执行注册时缓存的旧动作。因此，快速切换程序、浏览器标签或 WPS 内部文档时，更不容易执行上一个场景的内容。

## 状态和冲突

管理页会分别显示：

- 快捷键和操作摘要
- 规则来源
- 是否引用了已删除或不可用的动作
- 当前版本是否可以编辑该操作
- 最近一次 Windows 快捷键注册失败状态

注册失败不会在每次自动切换场景时反复弹窗。可以在管理页点击「刷新状态」集中检查。

全局规则仍支持按生效进程分组；规则列表支持多选和批量删除。免费版数量限制按账号中全部场景的动作快捷键总数计算，已有或同步得到的超限规则会保留，只限制继续主动新增。

## 限制与排障

- **快捷键没有响应**：先在管理页查看状态和注册失败信息，再使用 **设置 → 快捷键查询 → 快捷键占用查询** 定位 Quicker 内已注册的键。
- **停用后全局同键仍不触发**：这是预期行为。本地同键规则全部停用不会回退上级；删除本地同键规则才会恢复继承。
- **切窗口后执行了上一个程序的动作**：确认已升级到会在触发时重新核对窗口和规则的版本，并检查桌面 / 任务栏 / 资源管理器是否被当成同一场景。
- **与功能快捷键或其它入口冲突**：动作快捷键、扩展热键、热键联动和系统快捷键不要占用同一组合。
- **相对 1.x 的场景化与注册变化**：见 [动作快捷键（2.x 变化）](/v2/what's-new/others/action-hotkeys)。
