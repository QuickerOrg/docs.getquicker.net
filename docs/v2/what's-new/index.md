# Quicker V2 重要变化

Quicker V2 不只是更换界面。它升级了运行平台，并重做了动作、面板、场景管理、本地存储和云同步等基础结构。

本节集中说明相对于 Quicker 1.x 的重要变化。具体版本新增的小功能和问题修复，请另行查看版本更新记录。

## 先看结论

| 范围 | Quicker 1.x | Quicker V2 |
| --- | --- | --- |
| 运行平台 | .NET Framework 4.7.2 | .NET 10 for Windows |
| Windows 系统 | 可使用部分较旧的 Windows 系统 | 仅支持 .NET 10 官方支持的 Windows；不支持 Windows 7、8、8.1 |
| 程序位数 | 提供 x86 和 x64 相关构建 | 正式版本仅提供 x64 |
| 本地数据 | 动作页、通用数据等以较大的 JSON 对象保存 | 按账号隔离，并拆成可独立更新的数据项 |
| 动作参数 | 不同动作借用 `Data`、`Data2`、`Data3` 等字符串字段 | 使用带类型的结构化操作参数 |
| 动作与位置 | 动作主要依附于二维动作页 | 动作本体与面板、动作页、触发入口分开管理 |
| 面板 | 程序场景下切换多个二维动作页 | 按“场景 → 分组 → 动作”组织，可同时显示全局和上下文区域 |
| 场景管理 | 动作页、轮盘、手势和各种触发器分散在不同设置页 | 集中到“场景与动作管理”窗口 |
| 表达式 | 主要使用 Z.Expressions | 新增自研 QkEval，并保留必要的兼容路径 |
| 组合动作 | 旧执行管道和 HTML 调试日志 | 新执行管道、结构化记录、断点与单步调试 |
| 文本选择 | 文本悬浮窗 | 选中文本工具条 |
| 已移除能力 | 手机遥控器、文本悬浮窗等 | 不再提供，部分能力有新的替代方式 |

## 升级前最需要确认的三件事

### 1. Windows 版本和位数必须受支持

V2 只能在 .NET 10 官方支持的 Windows 上运行。Windows 7、Windows 8 和 Windows 8.1 不受支持；Windows 10 也需要属于官方仍支持的版本和分支。

V2 正式安装包只提供 x64 版本，32 位 Windows 同样不能安装和运行。

如果动作会在 Quicker 进程内加载第三方 DLL、COM 组件、数据库驱动或 Office 组件，还要确认这些依赖提供 64 位版本。

详细说明见[运行平台、系统要求与 64 位迁移](./platform-and-compatibility.md)。

### 2. V2 使用新的数据空间

V2 不会把 1.x 的 `quicker.db` 当作自己的日常存储继续写入。数据会经过迁移进入按账号隔离的新存储和新同步体系。

迁移完成后，1.x 与 V2 数据不会长期双向镜像。不要同时在两个版本中交叉修改同一批动作和设置。

详细说明见[数据存储与同步变化](./data-and-sync.md)。

### 3. 动作不再等同于一个面板按钮

V2 把“动作内容”和“动作出现在哪里”分开。同一个动作可以出现在多个面板场景，也可以被快捷键、轮盘、手势或其它动作引用。

从某个场景移除只会删除该位置；删除动作本体则会影响所有引用。整理动作前应先分清这两种操作。

详细说明见[动作存储、执行与调试](./actions.md)和[新面板窗口](./new-main-win/usage.md)。

## 推荐升级顺序

1. 在 1.x 中完成一次同步，并另外导出关键动作或做好数据备份。
2. 检查 Windows 版本和位数，以及动作依赖的 DLL、COM、Office 和数据库驱动位数。
3. 安装 V2，等待账号数据迁移和首次同步完成。
4. 先核对常用动作、动作页、公共子程序及重要触发规则。
5. 再开始整理新面板场景和分组，避免一边迁移一边大规模改动。
6. 确认 V2 已稳定使用后，再决定是否清理旧动作页或停止使用 1.x。

> **注意：不要把“切换新旧面板”理解为“切换 V1/V2 数据”**
>
> V2 中的新旧面板开关只改变弹出的面板窗口。它不等同于退回 Quicker 1.x，也不会让两代客户端重新共用同一套存储。
