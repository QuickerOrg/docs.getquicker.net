# 统一 AI 服务与模型设置

Quicker 1.x 的 AI 参数主要分散在具体动作或功能中。V2 新增统一的 AI 设置入口，把“连接哪个服务”“使用哪个模型”和“某项功能优先选择哪些模型”分开管理。

## 打开 AI 设置

以下入口名称适用于 2.3.2 及更高版本；2.3.1 及此前版本分别称为「AI 服务」「用途与模型」。

打开 Quicker 设置，在“AI”分类中选择：

- **服务商**：管理服务地址、协议、凭据、代理、超时和可用模型；
- **模型分配**：为不同用途设置按顺序尝试的候选模型。

当前内置服务模板包括 OpenAI、DeepSeek、阿里云百炼、火山方舟、智谱 AI、Moonshot AI、MiniMax、百度千帆和硅基流动等。

也可以连接 Ollama、LM Studio 等本机服务，或填写兼容 OpenAI Chat Completions、OpenAI Responses 协议的自定义接口。

## 服务连接与模型分开管理

一个 AI 服务连接负责保存供应商、协议、API 地址、认证方式、代理和超时等信息。连接建立后，可以从服务获取模型列表，也可以手工填写 API 模型 ID。

模型可以单独启用、停用、测试和修改显示名称。Quicker 还会记录模型是否支持流式输出、工具调用、结构化输出和图片输入等能力。

能力状态用于帮助选择模型，并不能替代服务商的实际接口说明。自定义或新发布模型的能力可能显示为未知，可以在确认后手工调整。

## 思考档位与能力实测

2.2.11 起，模型设置展示该模型可用的思考档位；没有已知多档能力的模型不会凭空出现档位选择。不同供应商或协议支持范围可能不同，不能把一种模型的档位直接套用到另一种模型。

可分别测试文本、工具调用和图像能力。工具与图像测试结果用于更新模型能力状态；认证或网络失败不代表模型一定不支持该能力，应先排除连接问题再测试。模型测试会实际调用所配置服务，可能产生用量。

## 按用途设置候选模型

V2 可以为日常文本处理与翻译、图片理解、Agent 与工具调用等用途设置候选模型顺序，也可以建立基于这些类型的自定义用途。

调用某项 AI 能力时，Quicker 会按照该用途的候选顺序寻找可用模型。连接被停用、凭据缺失或模型能力不符合要求时，该模型不会被当作正常候选使用。

“用此模型对话”可以直接测试当前模型，但不会修改用途的候选顺序。

## 新增组合动作 AI 模块

组合动作可以直接使用统一 AI 设置，不必在每个动作步骤中重复填写服务地址、模型和 API Key。本次新增 5 个模块：

- [AI 文本处理](/v2/xaction/modules/ai-text)：总结、改写、翻译、校对、改变语气，也可以使用完整系统提示词执行自定义任务；
- [AI 图片理解](/v2/xaction/modules/ai-vision)：识别图片内容、分析截图或按问题提取视觉信息；
- [AI 文本分类](/v2/xaction/modules/ai-classify)：从预先定义的分类中返回稳定 Key，便于连接条件判断和分支；
- [AI 结构化提取](/v2/xaction/modules/ai-extract)：按照 JSON Schema 从文本中提取对象和 JSON；
- [AI 交互对话](/v2/xaction/modules/ai-chat)：在流式对话窗口中继续追问，并由用户明确采用最终回答。

文本处理和图片理解既可以直接返回结果，也可以打开交互窗口调整回答。文本分类和结构化提取要求所选模型明确支持结构化输出；图片理解要求模型明确支持图片输入。

AI 交互对话会把会话保存在本机。动作分享不会携带会话历史，换设备后也不能使用原设备的会话 ID。每轮追问会根据当前任务场景重新选择可用模型。

原有的 [AI 调用](/v2/xaction/modules/ai) 模块也可以把「模型来源」切换为全局 AI 配置，按任务场景使用候选模型，并支持把流式内容写入文本窗口。旧动作默认仍使用步骤内自定义 API，不会因升级自动改用全局凭据。

## 凭据如何保存

API Key 不会直接写入普通 AI 设置 JSON。Quicker 使用 Windows DPAPI，以当前 Windows 用户身份加密后保存到本机独立凭据文件。

因此，复制设置文件到另一台电脑或另一个 Windows 用户后，原凭据通常不能解密。需要在目标环境重新填写 API Key。

凭据不会写入动作定义，也不会随动作分享。调用远程服务时，输入内容仍会发送给所选服务商；费用、日志、数据保留和隐私政策由对应服务商决定。

## 当前功能边界

2.3.1 起的可选凭据同步范围见下方说明；复制普通设置 JSON 仍不能代替密钥同步或重新配置。

统一设置页提供公共的连接、模型和用途配置，但不表示所有历史 AI 入口已经在同一版本中完成迁移。具体功能是否使用这里的候选模型，应以该功能页面和实际界面为准。

Agent 对话和外部助手 MCP 设置已有用户入口，MCP 默认关闭；部分网页元素选择等能力仍受发布限制。设置页按分类组织，2.2.11 改为分组卡片展示。具体启用、写入权限和客户端同意步骤见 [AI 与 Agent 现状](/v2/features/ai-and-agent.md)。

配置正式动作前，建议先执行连接测试和模型测试，并使用不含敏感信息的样例确认协议、模型 ID 和能力设置正确。

## 在设备间同步 API 密钥

以下功能从 **2.3.1** 起可用。

在 **设置 → AI → 服务商** 页底部勾选「在设备间同步 API 密钥」，并保存设置，可让 AI 服务的 API Key 和自定义 Header 随当前 Quicker 账号同步。该开关默认关闭，作用于 AI 服务配置整体，不是单个模型；离线账号不会上传。另一台设备需要登录同一账号，并使用支持此功能的版本。

**开启后凭据会上传到 Quicker 服务器，仅作基础混淆，不是端到端加密。** 服务端仍可还原，不适合把只允许本机保管的密钥放入此同步范围。它与本机的 Windows 凭据加密是两个不同边界，也不会把密钥放入分享的动作。

关闭并保存后，后续同步内容不再携带凭据；已经落到各设备的本机凭据不会因此自动清除，也不等于撤销服务商的密钥。需要撤销时，到对应服务商处理。若同步凭据无法解码，Quicker 保留当前设备已有的凭据；换设备后调用失败时，检查账号、服务配置和实际密钥，再运行能力测试。

**建议所有同步设备都升级到 2.3.1 或更高版本后再开启。** 旧客户端修改并同步 AI 设置，会清除凭据同步开关和云端的密钥字段；新版设备保留本机已有凭据，但需要重新开启同步。详见 [升级与回退](/v2/migration/upgrade-and-rollback#231-ai-数据按账号存放与密钥同步)。

## 2.3.2 · 服务商与模型分配

以下功能从 **2.3.2** 起可用。

2.3.2 起，在 **设置 → AI** 中使用「服务商」和「模型分配」两个入口：

1. 在 **服务商** 中添加连接，填写服务地址与凭据，检查连接；在同页管理该服务的模型，可「拉取模型」后加入，也可手动填写 API 模型 ID。
2. 确认模型启用及所需能力，再到 **模型分配** 为文本、图片或 Agent 等任务场景添加候选模型。
3. 在同一场景内拖动候选排序，或从候选的「⋯」菜单上移、下移、移除。优先顺序决定请求开始前选用哪个模型。

列表会说明模型被跳过的原因，例如连接停用、缺少密钥或所需能力未确认。**请求开始后发生错误，不会自动换下一个模型重试。** 应先检查错误、服务状态和配置，再重新发起。

在服务商页点击模型的能力标签，可探测支持情况，也可手动设为支持、不支持或恢复「自动（按目录判断）」。能力探测会真实调用服务，可能产生用量；探测失败不会直接判定为不支持。带 `*` 的能力表示用户修改过。

若候选只因所需能力未确认而不可用，菜单可提供「确认支持」。它等同手动把对应能力设为支持，**不是一次能力测试**；请先核对服务商说明或实际探测。明确不支持时不会提供这个快捷确认入口。

配置修改在切换页面或关闭设置时自动保存；候选顺序和能力状态仍应以保存后的界面为准。为某个模型选择「用此模型对话」只用于当前对话，不会改变任务场景的候选顺序。

## 2.3.5 · 自动保存与密钥更换

从 **2.3.5** 起，离开编辑控件、切换服务商或页面、关闭设置时都会尝试自动保存。修改服务地址、模型或密钥后，可移开输入焦点提交，再使用「检查连接」核对结果；有无效输入或保存失败提示时，先修正，不能仅凭切换成功认定已保存。

已保存的 API Key 显示为「已配置」。点击「更换」后输入新密钥，保存成功后替换原密钥；在新密钥尚未保存时点击「取消更换」，可放弃本次输入。点击「清除」并保存成功会移除该服务的本机密钥；这不会到服务商撤销密钥。需要停用密钥时，还应到服务商处理。

## 开发中：API 配置弹窗

以下说明依据 **2026-10-10 的开发代码，尚未包含在官网已发布的 2.3.6 中**。

从 AI 对话的「配置 API」进入，可在弹窗中直接管理服务与模型，不必先跳到桌面设置页；普通网页设置仍只保留外观入口。桌面「服务商」页继续可用，两处读取同一套服务商与协议定义。

1. 点击「添加」，选择服务商，再核对地址、API Key 和协议；代理、超时等选项在「高级」中。
2. 点击「获取模型」并加入需要的模型，或「手动添加」准确的 API 模型 ID。添加服务只保存连接配置，**不会自动填入模板默认模型，也不会把首个连接加入 Agent 的模型分配**。
3. 点选列表中的模型作为诊断对象，按需执行「测试文本」「测试工具」「测试图像」。测试需要明确的模型和有效地址；空模型不会改用模板默认型号。测试会真实请求配置的服务，可能产生用量；文本通过不等于工具或图像能力通过。
4. 回到对话模型菜单，明确选择要使用的模型；需要改变按用途的候选顺序时，再到「模型分配」调整。**点选测试模型不会替当前对话换模型，也不会改写用途优先顺序**。

输入失焦、切换服务或点击「完成」关闭弹窗时会尝试保存。若校验或保存失败，当前编辑会保留并显示错误，先修正再完成；不能把关闭按钮等同于无条件保存成功。单纯选择测试模型不会触发配置保存。

## 2.3.4 · OpenCode 连接兼容

2.3.4 修复了连接 OpenCode 服务时的会话请求头兼容问题。使用该服务仍需按服务商要求配置地址、协议和认证，并检查连接；不代表 Quicker 提供订阅或使用额度。
