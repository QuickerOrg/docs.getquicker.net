# AI 与 Agent 现状

这页说明 AI 写动作、模型配置和外部助手连接的常用入口。AI 结果需要检查，不同功能的开放范围以当前界面为准。

## 2.3.25 · 在线图库与动作编辑 {/* #icons-and-editing-2325 */}

在线账号可让助手搜索在线图库，为动作选择图标；也可明确要求“打开图标选择窗口”。在 **选择在线图标** 中可修改关键词、切换常用图库、全部图库或指定图库，并加载更多候选。双击图标或点击 **使用所选图标** 确认，取消不作更改；可从窗口打开第三方图库许可声明。

工作台、场景助手、组合动作设计器和脚本助手可使用对应范围内的图库能力；本地/离线账号不开放这项在线搜索。场景助手仍只修改本轮已选动作的主图标，编辑器中的图标仍需保存动作。MCP 可以搜索和导入图库图标，但不弹出用户选择窗口；图标导入成功不等于已应用到动作。

组合动作设计器中的助手还可编辑右键菜单、运行选项和关联配置，见[设计器内的 AI 助手](/v2/xaction/concepts/xaction-editor#designer-configuration-2325)。修改会留在当前编辑窗口，检查后由用户保存。

本版修复 AI 修改并保存动作时丢失未展示字段的问题。助手写回与编辑窗口内修改冲突时，可选择 **覆盖** 或 **放弃**；覆盖会替换冲突内容，操作前先保留仍需使用的手动修改。修改结果与对话压缩提示也会随“处理过程”折叠，便于查看最终回复。

## 2.3.23 · 工具结果与草稿确认 {/* #tool-results-2323 */}

助手的动作检查、保存及设置跳转会显示更具体的结果，例如“静态检查通过”“已保存 · 完整检查未完成”“已打开”或“等待点击链接”。保存成功不等于已通过完整检查，仍需根据提示验证；工作台中格式无效的动作链接会提示使用工具返回的完整链接。

在普通 AI 工作台修改当前动作草稿的标题、说明和图标时，确认方式与创建、保存草稿一致，不再为这类草稿外观修改单独询问。其他配置、正式动作写入、编辑器内修改及 MCP 调用仍沿用各自审批规则；这不表示助手可以直接改动任意动作。

首次初始化步骤参数导致的卡死问题已修复；取消或转向后，已经提交的用户输入会保留在对话历史中。

## 2.3.22 · 来源动作、运行记录与用量 {/* #source-and-usage-2322 */}

AI 助手可按当前权限读取和编辑来源组合动作。先打开或引用目标动作，再说明要改什么；作者只读、权限撤销或来源发生变化时，不能用强制保存绕过检查。保存前核对候选内容，保存不等于已运行验证。

排查组合动作时，可让助手查看结构化运行记录并结合报错分析；是否再次运行仍由你决定。步骤结果可能包含用户数据，提交给所选模型前应核对引用材料。

用量统计增加 **动作** 与 **诊断** 来源，纳入动作中的 AI 调用及设置页模型测试。供应商未返回用量时显示“未知”或“部分未知”，不将缺失用量视为免费；发生重试时可按实际请求分别计量。供应商账单仍是最终计费依据。

用户消息可复制，宽表格显示和长对话摘要恢复已改进；重复打开工作台不再留下空会话。设置、场景助手在关闭窗口后完成的回合仍可保存，迟到的旧记录不再覆盖新回复。

## 现在可以用

- **桌面 AI 工作台**：2.3.10 起直接开放，可从托盘、面板菜单的 **AI 工作台**、侧栏快捷按钮打开，也可绑定功能快捷键。2.3.13 起，暂存区的 **用 AI 写** 也使用桌面工作台，旧网页与手机 AI 入口已退役。见[2.3.13 的入口与接入变化](#2313--桌面入口与-mcp-接入)。
- **问问 AI**：2.3.17 起可从搜索、选中文本工具条及图片、文件菜单打开独立提问窗口，关闭后可在 AI 工作台继续同一对话。入口和材料范围见[问问 AI 说明](#2317--问问-ai-入口与文件操作)。
- **统一 AI 设置**：**设置 → AI → AI 服务 / 模型分配** 分别管理连接、模型和用途优选。说明见 [统一 AI 服务与模型设置](/v2/what's-new/ai-services-and-models.md)。
- **AI 助手界面**：2.2.5 起，可查看本机 Token 用量统计，并按时间、对话和模型查看用量及缓存命中；对话可按工作区分组，后台任务可从输入框上方展开查看。2.2.18 起，正式版支持选择工作区，打开历史对话时会恢复对应目录；导出对话后会显示保存位置，并可直接打开文件夹。未配置模型时，可从提示直接打开配置入口。
- **Quicker AI 写动作预览**：2.2.0 起，可在新版主窗口暂存区点击 **用 AI 写**，让 AI 生成或修改暂存动作；完成后暂存区会自动刷新。2.2.4 起，重复点击 **用 AI 写** 会复用没有草稿的空对话；还没有配置模型时，会沿用 AI 助手的配置入口。长对话压缩或重新打开后，已经生效的动作编辑规则仍会保留。生成结果先留在本机暂存区，确认可用后再执行「保留到场景」转为正式动作。功能仍在改进中，AI 可能写错步骤或逻辑，保存前请自行检查、试运行和调试。
- **五个组合动作模块**，共用上面的全局设置，不必在每个步骤里重填地址和 Key：
  - [AI 文本处理](/v2/xaction/modules/ai-text)
  - [AI 图片理解](/v2/xaction/modules/ai-vision)
  - [AI 文本分类](/v2/xaction/modules/ai-classify)
  - [AI 结构化提取](/v2/xaction/modules/ai-extract)
  - [AI 交互对话](/v2/xaction/modules/ai-chat)

首次使用 AI 能力前，需要在「配置 API」中添加服务商、模型和 API Key。多数服务需要自备账号和额度。API Key 默认只在本机加密保存，不随动作分享，也不随普通设置文件拷到另一台电脑。2.3.1 起可另行开启[设备间凭据同步](/v2/what's-new/ai-services-and-models#在设备间同步-api-密钥)，默认关闭。

## 用 AI 编写和修改动作

### 新建动作

在新版主窗口的暂存区点击 **用 AI 写**，说明输入、处理规则和希望得到的结果。例如：“读取选中的多行文字，去掉空行和重复行，保持原顺序，把结果复制到剪贴板。”

助手生成并保存后，先打开暂存动作检查步骤、源码或基础操作参数，再按需要试运行或调试。确认可用后选择 **保留到场景**，将它放入已有场景；在此之前，动作仍只保存在本机暂存区。

### 修改已有正式动作

2.3.7 发布快照调整了保存流程，见[保存已有动作](#237--保存已有动作)。以下暂存副本与单独写回的说明适用于 2.3.6 及更早版本；已有的旧暂存副本仍可继续使用。

在 AI 对话中通过 `@` 搜索并引用目标动作，同时说明要改什么、哪些行为需要保留。助手打开正式动作进行编写时，会建立或复用它的暂存编辑副本。后续保存先更新这个副本；原动作的面板入口和热键仍运行原来的内容。

检查并试运行暂存副本后，选择 **写回原动作**，或让助手发起写回并按提示确认。写回会用暂存内容覆盖原动作；它与新动作的“保留到场景”是两种不同操作。

在 2.2.24 中，如果提示原动作已变化，不要反复要求强制覆盖。先保留仍需要的修改内容，再丢弃旧编辑副本、重新打开最新原动作，将需要的改动重新应用。该版本不会自动合并两边的修改；2.2.25 起的合并能力见[暂存副本冲突处理](/v2/features/action-panel/action-drafts#原动作已变化时处理冲突)。暂存版本和删除限制见 [本机动作暂存区](./action-panel/action-drafts.md)。

:::note[2.3.1 起的写回方式]
2.3.0 及更早版本使用上面的确认流程。2.3.1 起开启 **完全控制** 后，助手可以按修改请求直接写回原动作，详情见 [动作保存与对话入口](#动作保存与对话入口)；其它审批方式仍需确认。仅要求保存草稿时，仍先留在暂存区。
:::

### 在设计器内修改

2.2.25 起，在动作编辑窗口配置好 AI 参数后，可点击右上角 **AI** 按钮，或按 `Ctrl+J`，打开设计器内的 AI 面板，用 AI 编写和修改当前动作。

详细操作见[在动作设计器内检查 AI 修改](#在动作设计器内检查-ai-修改)。

使用设计器内的程序助手时，助手修改的是当前编辑内容，成功的修改会显示在设计器中。检查结果后，仍需通过设计器的保存操作保存动作；保存到正式动作还是暂存区，取决于当前正在编辑的动作身份。

设计器内助手仍需通过设计器保存；独立 AI 对话在 2.3.7 中改为保存时按权限提交原动作。两者尚未实时共用同一份编辑内容，判断修改是否完成，应检查实际保存结果，而不只看助手回复。

### 运行并分析

2.2.26 起，动作编辑窗口的 AI 助手支持 **运行并分析**：可查看最近运行结果、定位失败步骤，并分析运行问题。适合试运行后把报错或异常步骤交给助手继续排查；分析不会替代你自己核对步骤与目标环境。

### 保存不等于运行验证

保存时的检查可以发现部分格式、参数或引用问题，但不会替你执行动作，也不能保证业务逻辑符合要求。设计器中已显示修改、已保存暂存动作、已写回原动作和已试运行成功，是不同的状态。

涉及文件修改、网络请求或界面操作时，先确认目标和输入，再选择合适的测试数据。试运行会真实执行步骤，并非无副作用的预览。复杂修改应同时检查相关变量、子程序调用和脚本，确认原有的不相关功能仍能正常使用。

## AI 助手工作区和历史对话

2.2.18 起，AI 助手正式版可以选择工作区。选择本地文件夹后，助手对普通文件的修改会直接保存到该文件夹；请先确认当前目录、备份和版本管理方式。

2.3.15 起，工作目录按会话独立保存；打开历史对话时使用该会话的目录。可以在会话空闲时选择另一个目录，保留原有消息和模型选择，不必新建对话。具体限制见[会话独立工作目录](#2315--会话独立工作目录与文件操作)。此前版本使用共享工作目录，切换行为不同。

2.2.22 起，标题栏的「导入导出」菜单统一提供以下操作：

- **导出对话文件**：保存为 `.jsonl` 文件，包含消息、工具输入输出和事件记录。正式版会把文件复制到剪贴板，可直接粘贴发送；导出后也可打开所在文件夹。
- **导入对话文件…**：选择收到的对话文件，导入后会以带「[导入]」前缀的标题保存在本机对话列表中，可再次打开查看。也兼容 2.2.20 版本导出的完整会话 JSON。
- **复制为 Markdown**：复制便于阅读的文本内容，不作为可重新导入的对话文件。

在 2.2.22 中，导入的对话仅供查看，不能继续发送消息；该版本的对话文件不打包附件文件、工作区文件或模型上下文，也不会重放工具操作。2.2.23 起的续聊条件见[导入后继续对话](#导入后继续对话)。发送前请检查是否含私人内容、路径或工具返回的数据。

新版对话文件请用 **2.2.22 或更高版本**导入，旧版离线查看流程不保证兼容；已有普通对话无需迁移。工作区回退限制见 [升级与回退](/v2/migration/upgrade-and-rollback#2218-远程文件账号与-ai-助手工作区)。

### 针对步骤提问

2.2.22 起，右侧设计器中的步骤可拖到对话输入框，或通过「加入对话」加入步骤引用。输入修改要求后再发送，便于助手定位要处理的步骤；加入引用本身不会运行步骤。

右上角的同一图标可显示或隐藏右侧栏；右侧标签栏的「+」可打开动作选择页。关闭 Agent 窗口后，正在进行的任务会继续在 Quicker 后台执行；需要停止时请使用任务的停止操作，退出 Quicker 则会停止后台任务。

## 连接外部助手

2.3.13 的三种接入指引见下方[桌面入口与 MCP 接入](#2313--桌面入口与-mcp-接入)。

在设置中打开外部助手的 MCP 设置页，可按页面指引连接本机外部助手：

1. 启用 MCP，功能默认关闭。
2. 按所用助手的安装指引配置连接。请求批准模式下，首次连接时在 Quicker 中同意；2.3.5 起，Agent 或 MCP 选择「完全控制」时直接连接。
3. 需要编写动作时，另行开启“允许 MCP 写入”；仅连接不等于获得写入权限。
4. 2.2.11 起，可在“已同意的 MCP 客户端”中删除授权记录，该助手下次在请求批准模式下连接需要重新同意。完全控制下仍直接连接，且自动连接不会新增已同意记录。

连接信息与令牌从自己的设置页获取，不要把令牌贴入公开动作或文档。

**文件访问范围与内置 Agent 不同。** 内置桌面 Agent（AI 工作台、问问 AI）的普通文件工具可以按请求访问工作区外的磁盘路径，受当前 Windows 用户权限和操作审批约束；设计器、设置等内嵌助手仍使用各自的工作范围。外部 MCP 的文件工具只能访问 Quicker 工作区、本会话已打开的动作槽位，以及已注册的只读逻辑挂载。开启“允许 MCP 写入”或选择“完全控制”均不会放开外部磁盘路径，也不会把外部助手自己的项目目录自动绑定为 Quicker 工作区。

例如，通过 MCP 将临时目录中的 PNG 移入动作槽位时，如果源文件位于上述范围外，`move_file` 会拒绝访问；这与 PNG 格式无关。导入图标应使用[图标导入入口](#icons-and-tool-details-2320)并按权限确认，而不是用文件移动代替；2.3.25 起还可搜索、导入[在线图库图标](#icons-and-editing-2325)。

通过 MCP 新建的动作仍先保存在暂存区，检查后保留到场景。2.3.7 起，修改已有正式动作时沿用[保存已有动作](#237--保存已有动作)的提交与批准规则；2.3.6 及更早版本先保存编辑副本，再写回原动作。允许 MCP 写入不等于新建动作自动成为正式动作；完成后请在 Quicker 中检查实际保存位置和内容。

## 对话与图片输入

2.2.18 起，新建对话可选择工作区，重新打开历史对话时会恢复对应目录；导出对话后会显示保存位置，并可直接打开文件夹。工作区设置会随对话保留，回退到不支持自选工作区的旧版后，不要继续编辑对应项目对话。

2.2.19 起，长对话会在接近模型上下文上限时提前压缩历史，并保留工作区与已应用的编辑规则，减少长任务中断。输入框中的 `@` 动作和公共子程序搜索会预热目录并在本地排序，中文标题和所在位置的匹配响应更快。

2.2.20 起，对话右侧可打开本对话中动作或触发器的设计器，便于边聊边检查草稿。切换尚未保存的文档时可以取消切换。AI 设置中的对话窗口可按模型配置，填写时请以对应服务商的模型限制为准。空对话还提供「如何配置 MCP」入口；外部助手安装指引补充了 WorkBuddy / CodeBuddy。

2.2.17 起，桌面 AI 对话使用统一界面，复制回复、采用结果和取消操作集中在对话与输入区域。AI 助手继续追问时，会保留最近有效的动作或触发规则跳转卡片，便于回到刚生成的内容检查和试运行。

2.2.11 改进“用 AI 写”对当前空对话的复用；有草稿的空对话经确认关闭后保留归档。图片缺少本地文字识别组件时，可按提示安装再识别；需要直接理解图像内容时，还应选择支持图片输入的模型。

## 导入后继续对话

2.2.23 起，导出的对话文件可携带已经保存的模型会话。使用**同一种 Agent 入口**导入，并且文件中有可恢复的模型会话时，可以继续发送消息；缺少模型会话、来源入口不匹配或恢复失败时，仍按只读对话导入。较早版本导出的只读文件不会因为升级而自动获得续聊能力。

导入会新建一条带「[导入]」前缀的对话，不覆盖原对话。可续聊对话使用**导入时当前选择的工作区**，不会自动复制发送方的工作区文件或附件；继续让助手处理文件前，请先核对本机目录和所需文件。导入本身不会重放历史工具操作。

## 让 AI 协助分享动作

2.2.23 起，可以让助手为正式动作准备分享说明、图标和更新摘要，再打开分享页面供本人核对并提交。具体步骤和暂存草稿的处理见[分享动作与公共子程序](/v2/features/action-sharing#让-ai-协助分享动作)。

## 对话界面

以下界面功能从 2.2.24 起可用。

### 在对话中选择上下文窗口

在输入区域打开模型选择菜单，进入所选模型的「上下文」子菜单，选择界面提供的档位。只有存在至少两个可选窗口大小时才会出现此入口；看不到该项不一定是配置错误。

「默认」使用模型配置的工作窗口；其它档位以界面显示的模型容量为界。选择按模型记在本机，切换回该模型时会沿用；重新选择「默认」可恢复默认预算。如果保存的档位已不再提供，会退回当前默认值。上下文用量显示随选择更新，后续请求使用相应预算；这不会改变服务商实际允许的容量，也不会还原已经压缩掉的原始历史。

### 引用文字和收起侧栏

选中对话记录中的文字，点击浮出的「添加到对话」，可把内容作为普通引用文本加入输入草稿，再补充问题并发送。2.2.24 中可以直接编辑或删除这些引用文本；添加引用本身不会发送消息。

点击左侧会话栏顶部的「收起侧栏」可给对话留出更多空间，再点「展开侧栏」恢复。展开或收起状态保存在本机，重新打开时会沿用。收起侧栏不会归档或删除对话，也不会停止后台任务；折叠会话分组时保留滚动位置。

## 2.2.25 新增与改进

:::note[适用范围]
本节能力已包含在 2.2.25 中。2.2.24 的引用仍是可直接编辑的普通文本；升级后可使用下面的独立引用块和其它改进。

### 引用对话中的一段内容

在对话记录中选中需要追问的文字，点击浮出的「添加到对话」。选中文字会作为「所选文本」引用块加入输入区，原有草稿保留；点击引用块可展开检查，用旁边的移除按钮可删除单个引用。

可以连续加入多段引用，再输入问题并发送。添加引用不会立即发送消息或执行其中的操作；移除引用也不会删除原聊天记录。

### 手动压缩上下文

长对话中可单独发送 `/summarize`，把较旧的模型上下文整理成摘要后继续交谈。在空输入框键入 `/` 可打开命令补全，点击候选项或按 `Tab` / `Enter` 只补全命令，随后仍需发送。

发送时只保留该命令，不要附加问题、图片或引用块，否则会作为普通消息处理。压缩会保留界面中的聊天记录，并尽量保护最近消息和关键要求；它改变的是后续请求携带的上下文，不能保证每次都能进一步缩小。没有可安全压缩的旧消息时会给出提示；压缩失败或取消时保留原上下文，可按状态提示继续或重试。生成摘要会调用所选模型，可能产生相应的用量。

### 调整会话侧栏

侧栏展开时，拖动它与对话区之间的分隔线可调整宽度，双击分隔线恢复默认宽度；宽度也会记在本机。窗口变窄时会限制侧栏宽度，为对话保留空间。标题较长时，将鼠标停在对话标题上可滚动查看完整标题。

### 在动作设计器内检查 AI 修改

桌面动作设计器可从标题栏「AI」按钮或 `Ctrl+J` 打开助手面板。助手修改当前正在编辑的程序，完成后可通过改动标记和完成卡片定位修改，再决定是否保存或撤销。它与独立 AI 对话中的暂存副本写回流程不同，详见[动作编辑器中的 AI 助手](/v2/xaction/concepts/xaction-editor#设计器内的-ai-助手)。

### 命令批准和外部助手授权

需要确认命令时，卡片只有在本次命令支持记住同类批准时，才显示「批准同类」，并说明适用范围。多行脚本或不能归为可记住命令的内容仍需逐次确认；没有该按钮不表示命令执行失败。多行脚本的摘要会注明行数，确认前应查看实际内容。2.3.5 起，完全控制下不再逐次确认命令，权限范围见[完全控制与工具恢复](#235--完全控制与工具恢复)。

外部助手的「已同意的 MCP 客户端」列表会显示程序路径，便于辨认和撤销授权。同一安装位置下，仅版本号目录变化的客户端升级可沿用已有同意；更换其它目录或程序文件名不能据此视为同一个客户端。客户端同意与「允许 MCP 写入」仍是分别控制的权限。

### 正式动作与暂存副本同时被修改

本节说明旧暂存副本的写回；2.3.7 中新打开已有动作的保存冲突处理见[保存已有动作](#237--保存已有动作)。

2.2.25 起，写回暂存编辑副本时会尝试保留原动作中不冲突的最新修改；有冲突时保留两份内容，并提供「让 AI 协助合并」。合并结果先存回草稿，检查和试运行后仍需本人确认写回。具体边界见[暂存副本冲突处理](/v2/features/action-panel/action-drafts#原动作已变化时处理冲突)。

## 2.3.9 · 编写、搜索与管理动作

以下说明依据 **2.3.9 发布快照**，开放下载状态以[官网版本记录](https://getquicker.net/V2/Versions)为准。

AI 工作台与 MCP 的动作编写能力扩展到 **Quicker 脚本动作**和常用基础动作，例如打开网址、文件、文件夹、运行程序、等待、发送文字及按键。描述目标即可让助手选择合适的动作类型；需要组合动作或脚本动作时，也可明确指定。修改已有动作时应保留其类型，不把其他类型的内容直接覆盖进去。

新建动作仍先留在暂存区，检查后再 **保留到场景**。编辑已有动作时沿用[保存已有动作](#237--保存已有动作)的权限与冲突处理；保存前复核当前原稿，遇到其他编辑器已保存的新内容时，保留修改并重新读取、合并。脚本编辑器内助手仍只修改当前编辑内容，保存由用户决定。

工作台中的动作链接可展开 **运行、最小化后运行、编辑** 等操作。这里运行的是最近保存的版本，不会自动保存当前修改，也不会把暂存动作转为正式动作。独立 AI 对话与 MCP 可按运行权限试跑脚本和基础动作、读取运行记录；这与脚本编辑器内助手不会自行运行脚本的规则不同。试跑会真实操作文件、窗口等目标，停止不代表撤回已经发生的操作。

可要求助手按最近编辑、最近使用或最近安装排序查找动作，并限定正式动作或暂存稿。还可查询、复制动作、查看引用或恢复历史版本。引用查询不能穷尽其他动作正文和动态脚本中的调用，空结果不等于没有依赖；删除前仍需检查引用范围和批准提示。历史恢复与撤销只恢复动作内容，不会回滚动作已经执行的外部操作。

2.3.8 起，对话直接显示当前模型名称，发送新消息时自动收起脚本最近运行卡片；收起卡片不会停止运行或删除记录。

## 2.3.10 · 桌面 AI 工作台

桌面工作台不再需要开启实验开关。2.3.10–2.3.12 曾保留 **在网页版中打开** 入口；**2.3.13 起已退役**，请使用桌面工作台，已有桌面对话继续保留。

### 整理会话与保留输入

侧栏支持 **按时间分组** 或 **按工作区分组**，可折叠分组及整个侧栏。已有会话中未发送的纯文本草稿只保存在本机，不包含引用和附件；重新打开后，发送前请检查输入内容和所需附件。

会话右键菜单提供 **永久删除**，会清除会话及附件；按住 `Shift` 点击可跳过确认。永久删除不能通过归档恢复，也不会回滚会话中已经执行的文件修改或动作操作。需要保留的内容请先导出或另存。

### 引用动作与检查修改

组合动作设计器和脚本助手中的动作、公共子程序引用更易辨认，悬停可核对引用身份；复制粘贴完整引用时可保留其身份。经过只支持纯文本的应用后，不保证仍保留引用信息，发送前请重新核对目标。引用只提供上下文，本身不授权助手运行或修改目标。

可要求助手修改动作图标、标题、说明和菜单，未要求修改的信息应保留。检查后，设计器内助手仍需通过编辑器保存，独立对话仍按现有提交与批准规则处理。工具调用可查看完整输入输出，命令执行时可查看实时反馈；看到输出不等于操作已完成或已保存。

桌面助手手动选择模型后会立即记住选择，不必先发一条消息；选择用于后续请求，不替换正在运行中的回合。模型可用推理档位的配置见[服务与模型设置](/v2/what's-new/ai-services-and-models#2310--连接检查与推理档位)。

回退旧版可能清除新增的分组偏好和输入草稿，详见[2.3.10 升级与回退](/v2/migration/upgrade-and-rollback#2310--ai-工作台与执行默认值)。

## 2.3.13 · 桌面入口与 MCP 接入

### 工作台、预览与分享

桌面网页版 AI、网页版动作设计器和手机 AI 已退役，旧网页入口及面板 `Ctrl+右键` 的网页入口不再可用。请从 **AI 工作台** 或暂存区的 **用 AI 写** 进入桌面界面。已有桌面对话继续保留，不需要重新创建。

工作台和外部助手统一使用桌面动作编辑器预览、编辑动作，并在桌面窗口确认分享。已有编辑器中的未保存内容会保留；出现忙碌或版本冲突提示时，先检查、保存或备份手头修改，再处理冲突，不要把助手回复当成已经覆盖成功。分享仍需检查发布内容并完成确认。

工作台支持用上下方向键浏览 **当前会话** 的输入历史，回复中的换行显示也更准确。若回复提示未保存，可在工作台重试保存；遇到损坏的对话记录时不再直接覆盖原记录，但这不表示损坏内容已自动恢复。

### 选择 MCP 连接方式

启用 MCP 后，在外部助手设置中按客户端能力选择一种方式：

| 页签 | 用法 |
|---|---|
| **AI 自动配置** | 复制提示词给目标助手，让它检查自己的运行环境和配置格式，再完成连接。提示词含本机访问密钥，请勿公开分享 |
| **HTTP 连接** | 优先用于支持本机 Streamable HTTP 的客户端。复制设置页的 URL 与 Token，认证使用 `Authorization: Bearer <Token>`；只填 URL 不足以连接 |
| **stdio 连接** | 不支持本机 HTTP 时使用。将程序随附的 `quicker.mcp.exe` 完整路径填入 `command`，参数留空；桥接工具自动读取本机 Quicker 设置，无需另填 Token 或安装脚本 |

使用自己设置页中显示的地址、端口和程序路径。一个客户端选择 HTTP 或 stdio 其中一种，避免重复添加。Quicker 需要保持运行；云端、容器或其他隔离环境中的助手应先确认能访问这台 Windows 电脑，本机地址不会自动指向远程电脑。

首次连接批准、**完全控制**、**允许 MCP 写入**及动作运行确认仍按现有权限设置执行；复制连接信息不等于授权修改或运行。配置完成后，用一次只读查询确认工具实际可用。

Token 应保存在客户端的用户级配置中。正常升级不要求重新生成；主动重新生成后，所有直接 HTTP 客户端需更新 Token 并重新加载连接，stdio 桥接会自动读取新密钥。

## 2.3.20 · 导入图标与查看执行详情 {/* #icons-and-tool-details-2320 */}

在 **场景、动作与触发管理** 中选中动作后，可让旁边的助手“为所选动作生成并应用图标”。修改限于本轮已选动作的主图标；需要改其他动作时，先重新选择。工作台中的助手也可为已有动作修改图标、标题、说明等外观信息，仍按当前权限和保存规则处理。

助手支持从本机 PNG、JPEG、SVG 文件导入图标，也可使用生成的 SVG。在线账号导入会上传到图标服务；离线导入只保存在本机，不能仅凭动作中的图标引用在其他电脑显示。请明确说明要修改的动作和期望效果，完成后检查实际图标；图标导入成功本身不代表已经应用到动作，设计器内的修改仍需保存。

工具调用详情按**结果、输入、调用记录**分组，可搜索内容、查看及复制完整结果。已回答的提问会收进执行过程；调用失败与动作本身的业务状态分别显示，看到命令输出不等于执行已完成或修改已保存。

浏览器操作改进了权限同步与断线恢复。连接恢复后仍需核对当前网页、目标和权限，不能将连接成功当作某次写入已经完成。**问问 AI** 同时打开多个窗口及切换会话时的目标窗口跟随问题也已修复；发送前仍应查看当前目标标签。

导入图标和 SVG 的兼容边界见[升级与回退](/v2/migration/upgrade-and-rollback#capture-sync-and-icons-2320)。

## 2.3.19 · 窗口背景与提问示例 {/* #window-context-2319 */}

从其他程序唤起 **AI 工作台** 或 **问问 AI** 时，输入区的目标窗口标签会显示本次来源。除窗口标题和程序名外，助手会按窗口支持情况读取当前文件夹、选中文件路径、网页地址、活动文档和选中文字。自绘界面、权限限制或不支持的程序可能无法提供完整信息；标签不是“已读取整个窗口”的保证。任务需要时，助手还可通过观察工具进一步读取可见文字，仍受当前权限与工具设置约束。

- **核对来源**：发送前查看目标窗口标签及提示；切换目标后，旧窗口迟到的结果不会补入当前草稿。
- **重新读取或取消**：打开目标窗口菜单，按需重新读取背景或取消当前读取；清除目标也可移除当前草稿的窗口背景。从外部窗口再次唤起会更新来源，并保留已经输入的正文。
- **等待选区补入**：用问问 AI 快捷键唤起时，先显示提问窗口，再补入选中文字或文件路径清单。读取失败时可继续输入，或手动添加附件；发送前核对材料。

背景作为材料随问题发给所选模型并保存在对话中，可能包含窗口标题、路径、网址和选中文字。选中文件的路径清单不等于文件内容；后续读取文件或操作窗口仍按当前权限设置执行。回退旧版后重新编辑或发送消息时，可能需要重新附加背景，见[升级与回退](/v2/migration/upgrade-and-rollback#preferences-and-ai-2319)。

工作台欢迎示例现在按能力分组，并结合已有动作及剪贴板内容提供示例。选择后先检查填入的问题和附件，再明确发送；剪贴板材料不会仅因显示欢迎页就自动发送给模型。

2.3.19 起，MCP 的 **AI 自动配置** 页签精简了操作，**HTTP 连接** 可显示完整密钥。复制前核对目标客户端；截图或分享配置时应遮盖完整 Token。

## 2.3.18 · 让工作台直接帮忙做事 {/* #desktop-tasks-2318 */}

除了编写动作，还可以在 AI 工作台直接描述一次性的任务，例如“查找本机某个文件并打开”“启动已安装的程序”，或让助手对当前目标窗口执行操作。查找文件依赖本机可用的文件索引；没有找到结果时，可提供更明确的目录或文件路径。执行一次性任务不会自动创建或保留一个新动作。

输入区的目标窗口可切换或清除。发送前核对目标；窗口已经关闭或身份发生变化时，应重新选择，不要把旧目标当成当前窗口。文件、程序和窗口操作会真实影响本机环境，按当前权限档位请求批准；停止会话或撤销动作内容不等于撤回外部操作。

助手调整动作、动作页及触发规则时，继续提供操作确认和变更记录。动作引用候选显示图标和两行信息，便于核对目标。带独立工作目录的会话仍可使用已配置的联网搜索；DeepSeek 思考模式的多轮对话及批准后的历史回传兼容问题也已修复。

### 自定义 MCP 集成的写入方式

2.3.18 起，`quicker_eval` 不再用于写入；**2.3.22 起该工具已移除，读取也改用专用工具**。升级后刷新客户端的工具清单，清理旧提示词或脚本中的调用；例如查找和读取设置使用 `quicker_settings_search`、`quicker_settings_getvalues`，读取表格使用 `quicker_tables_listrows`。动作管理、动作页调整、动作配置和触发规则写入仍使用对应专用工具。

停止运行改用 `quicker_run_stop`，不要再向 `quicker_run_output` 传 `stop=true`；合并预览改用 `quicker_merge_draft_preview`，`quicker_merge_draft` 只提交合并候选。旧调用不会自动转换，请按当前工具参数更新集成。

以实际工具列表和参数说明为准；不同助手入口的工具范围不同，浏览器写入工具不会因这次调整自动向 MCP 开放。

普通用户继续通过助手描述需求即可。已有“允许 MCP 写入”、客户端同意和运行批准仍分别生效；升级不会自动授予新的写入权限。

## 2.3.17 · 问问 AI 入口与文件操作

在搜索框输入 `??` 或 `？？` 开始提问；按 `Enter` 会尝试附上当前选中文字，按 `Ctrl+Enter` 则只发送问题。选区获取失败时会保留问题草稿并提示手动发送，不会自行发送。也可使用已配置的 **问问 AI** 功能快捷键，或从选中文本工具条、图片和文件的右键菜单打开。工具条的快捷项需在场景的“选中文本”设置中自行添加，不会自动插入已有工具条。

问问 AI 使用独立小窗；关闭后同一会话会出现在 AI 工作台，点击小窗中的“工作台”可立即切换。选中文字会成为“选中内容”附件，问题正文不会重复粘贴选区。图片菜单附上当前图片；文件菜单只附上所选文件的**路径清单**，不会因打开问问 AI 就读取或上传文件内容。检查附件和问题后再发送。

2.3.17 起，AI 助手处理普通文件时，删除会移入回收站，覆盖前会备份原始内容；在“请求批准”和“替我审批”下，删除、覆盖、编辑及移动/重命名需确认。“完全控制”会按所选权限自动执行，输入区会提醒备份重要文件。确认前请核对目标路径与操作；这些保护不等于文件修改可以自动撤销。工具参数无效时会在请求批准前提示，编辑失败或模型回复中断时可按界面指引继续。

## 2.3.15 · 会话独立工作目录与文件操作

### 为会话选择目录

在 AI 工作台的工作目录入口选择文件夹，只影响当前会话。新草稿采用最近一次有效选择，初始化后独立保存；旧会话没有目录记录时使用默认目录。

- 当前会话正在执行、等待批准或工具回复时，不能修改目录；其他会话正在运行不影响本会话选择目录。
- 修改目录不会搬迁文件、创建副本或清空聊天。已启动的后台任务继续使用启动时的目录，新任务使用新目录。
- 原目录失效时仍可查看历史并重新选择目录，但不能继续在失效目录执行，也不会自动切到别的目录。
- 不同会话选中同一个文件夹时，共享其中的实际文件；独立目录设置不等于隔离文件副本。

设置和动作编辑器内的助手仍使用各自的工作范围，不继承桌面会话的目录。准备回退时，先看[会话与问题历史的兼容限制](/v2/migration/upgrade-and-rollback#2315--会话目录与截图-ai-历史)。

### 操作回复中的文件

点击 AI 回复中的本地文件链接，可在资源管理器中定位。右键菜单提供打开、复制路径或文件名、复制文件或文本内容、另存为，以及添加为附件。文件仍需存在于当前电脑，复制路径不等于复制文件内容。

### 整理话题与查看处理过程

话题列表可标记未读、展开更多话题，并区分运行中、待处理和完成未读状态。助手的处理过程可以整体折叠，等待与思考行采用更紧凑的布局。

动作预览模式中也可以向 AI 提问、分析动作内容；预览仍不允许写回修改，动作本身的权限和调试限制仍然适用。

## 当前功能边界

Agent 对话与外部助手设置已有用户入口，但不代表所有开发中的浏览器、桌面操控能力都已开放。“选网页元素”等仍受发布限制的入口，以当前软件界面为准。

不要把 1.x 的手机遥控或 Android 局域网遥控当成 V2 已有能力。V2 已移除手机 App 遥控器，目前也没有承诺替代方案。见 [不再支持的功能](/v2/what's-new/not-supported.md)。

具体功能是否已经改用统一候选模型，以该功能自己的页面和软件界面为准。

<a id="开发版对话中的保存撤销与输入草稿" />

## 对话中的保存撤销与输入草稿

以下功能从 2.2.26 起可用。同版修复了粘贴附件的导入问题，图片文字识别内容改为按需读取。

独立 AI 对话的聚合变更卡片新增「撤销」。一轮中多次保存同一动作时，可恢复到该轮第一次保存之前的内容；只有记录了完整快照、回合已结束且没有后续修改冲突时才能恢复。它与桌面设计器的「撤销本轮」是两个入口。

这里撤销的是卡片记录的程序内容保存，不会删除新建动作、改变场景位置，或撤回动作运行产生的文件、网络等结果。写回原动作后的撤销会恢复正式动作，但不会重建已被写回移除的暂存副本。涉及多个程序时可能只有部分恢复成功，应按卡片逐项结果处理，不能只凭点击过「撤销」就认为全部恢复。

新对话中尚未发送的文本和引用可在本机保留；同一工作区保留一个新对话草稿入口。重新打开后可继续编辑，发送前仍需检查引用和附件。输入草稿尚不是已发送的历史消息，也不会因为恢复输入框而自动发送。

<a id="开发版设置与场景窗口中的-ai-助手" />

## 设置与场景窗口中的 AI 助手

2.3.0 起，在「设置」或「场景、动作与触发管理」窗口中，点击标题栏的 AI 按钮，或按 `Ctrl+J`，可打开右侧助手。先配置 AI 服务与模型，再说明要查找的设置、目标场景和已有动作，例如「把主题改成深色」或「在 Chrome 场景为翻译动作设置快捷键」。场景窗口会提供当前场景、页签和部分选中项作为上下文；涉及继承规则时，仍要明确希望修改哪个场景。

助手可查找设置、修改已支持的设置项，并为已有动作配置支持的触发规则。回复中的设置或触发链接可打开相应页面，便于核对实际结果。部分列表或尚未支持直接修改的设置只提供页面入口，需要本人继续操作；手势绘制、轮盘布局以及动作程序编写也应到对应编辑器完成。

写入仍受当前审批方式、设置校验和账号权益限制。若当前页面有无效或无法提交的输入，请先修正，再发送请求。回合结束后检查变更记录与页面结果，并实际试用触发规则；这里尚不支持设计器那样的「撤销本轮」。如果手动编辑与助手修改发生冲突，请按提示重新读取和核对，不能仅凭助手回复认定全部保存成功。

<a id="开发版动作保存与对话入口" />

## 动作保存与对话入口

:::note[适用范围]
以下变化从 **2.3.1** 起可用。
:::

### 完全控制下写回原动作

本节描述 2.3.1–2.3.6 的暂存写回流程；2.3.7 改为[保存时提交已有动作](#237--保存已有动作)。

助手修改已有正式动作时仍先保存暂存副本；开启 **完全控制** 后，若请求要求应用修改，助手可以直接写回原动作，不再逐次弹出写回确认。其它审批方式仍需确认。**仅保存到暂存区** 不代表已应用，回复中应区分「已保存到暂存区」和「已应用到原动作」；新动作仍使用 **保留到场景**。

直接写回仍检查当前草稿版本、原动作是否变化及是否只读，并尝试合并不冲突的修改。存在冲突时保留两边内容；完全控制不会跳过这些检查。写回前会保存原动作的完整版本，备份失败则停止写回。若提示新版本历史未完整记录，应核对正式动作与本地历史，避免把提示当作没有写回。

助手保存时可附带简短的版本说明，供暂存历史和写回后的动作历史查看。它描述这一版的变化，不会代替动作标题或说明。暂存手动备份的保留范围见 [本机动作暂存区](./action-panel/action-drafts.md#手动备份和版本说明)。

### 新对话引用最近修改的动作

尚未发送消息的新对话中，输入区附近可显示 **最近修改**，按实际修改时间列出至多六个动作，也可能包含标有「暂存」的动作。点击候选只把动作引用加入输入框，会保留已有文字和引用；继续填写要求并发送后，助手才开始处理。这里不是最近打开的动作列表，没有可用候选时不会显示。

### 设计器与对话中的检查入口

设计器内的组合动作助手也可修改动作标题和说明。这些改动会纳入本轮变更检查及「撤销本轮」；回合结束后，除了步骤，还应检查标题、说明是否准确。若期间又有手工修改，请按冲突提示处理。

独立对话中的思考和连续工具调用可以收起后再展开查看；回复正文和向用户提出的问题仍直接可见。折叠只改变显示，不会停止正在运行的任务。

2.3.1 起进一步合并相邻工作过程，折叠标题会概括实际执行的操作，并提示失败情况。需要核对某次读写或报错时，展开查看明细；标题中的操作摘要不代表所有修改都成功，也不代替动作结果检查。

<a id="开发版模型附件与提问" />

## 模型、附件与提问

以下内容从 **2.3.1** 起可用，适用于已开放的组合动作 / 公共子程序设计器、脚本编辑器及设置、场景助手；附件的适用范围另见下方说明。

### 为当前对话选择模型

在助手输入区打开模型菜单，选择模型及其支持的思考档位。选择只影响当前对话，不会替换其他对话的选择，也不会改写设置中的用途与优选模型；选择默认模型时跟随对应用途的配置。

这是 2.3.1 至 2.3.3 的选择方式。2.3.4 起的独立保存与新对话初始模型规则见[会话模型与恢复](#234--会话模型与恢复)。

新选择从下一轮请求起生效，当前回合运行期间不能更改。切换模型后，原思考档位不受支持时会回到「自动」；模型不可用或当前历史与模型不兼容时，请按提示重新选择。切换可能使提示缓存失效，下一轮用量可能增加。

### 给设计器助手添加附件

组合动作 / 公共子程序设计器和脚本编辑器的助手输入区增加「添加附件」。可以选择文件、粘贴图片或文件，也可从资源管理器拖入；长段粘贴文本会作为文本附件。**2.3.1 的设置和场景助手没有附件入口**，后续变化见[2.3.2 · 窗口助手](#232--窗口助手)。

每条消息最多附加 **8 个文件**，每个文件最多 **8 MiB**。优先使用图片或文本、代码、JSON 等可识别文件；不支持的文件类型会改为路径文本，不能据此认定助手已读取文件内容。附件加入后先核对卡片，发送前可删除；加入附件本身不会发送消息。

直接理解图片需要支持图片输入的模型；文字识别结果只能补充图片中的文字，不能代替图像理解。已经发送的图片会进入对话历史，后续追问仍可使用，历史消息也可显示缩略图。不要把这理解为导出的对话文件已经打包所有图片原文件。

### 截图与选择窗口

打开附件菜单，选择「截图」或「选择窗口」。选择窗口时，助手所在窗口会暂时隐藏，点选目标窗口后恢复；按 `Esc` 可取消。成功后通常加入两个相邻附件：窗口信息文本和窗口截图，文本包含可读取的进程、路径、窗口标题和类名等信息。

发送前分别检查两个附件；窗口包含私人内容时，可删掉截图，只保留必要的窗口信息。若只剩一个附件名额，会仅加入信息文本，并提示未附加截图。截图和窗口信息仅在主动选择后采集，不会因为打开助手就自动发送。

### 回答助手的问题

助手需要澄清时，输入区上方会出现独立作答区。多道问题逐题填写，可用上一题、下一题检查；切题会保留本次作答草稿。2.3.1 至 2.3.2 需要在最后提交全部答案，选择一个建议选项或填写文字本身不会提交。

**2.3.3 起，窗口内助手的确认方式有变化**：单选题点击选项会确认当前题并前进；在最后一题且其他题都已回答时，会提交全部答案。多选题可以先勾选或取消多个选项，再点击确认；自由输入可按 `Enter` 确认，`Shift+Enter` 用于换行，输入法确认候选词不会提交。还有漏答题时会返回补答。提交前需要复查时，请在确认最后一题前使用上一题返回检查。

提交后，消息记录可展开查看实际提交的答案。未提交的草稿、取消或跳过的问题不能当作已答复的要求。脚本助手新建脚本或新增行为时的确认流程见[脚本 AI 助手](/v2/script-action/assistant#先确认需求再修改)。

### 反馈未完成的任务

设计器、脚本、设置和场景助手的一轮对话结束后，可从反馈入口说明问题；失败或中止时也可能显示「反馈给我们」。选择分类，填写问题与期望效果，并检查窗口中的「将发送的摘要」「信号」和「回合记录（已脱敏）」后再提交。若本机缺少完整过程，窗口会提示只包含摘要。

反馈需要登录 Quicker 账号；体验或离线账号可先「导出反馈包」到本机。**提交会把预览内容上传到 Quicker 服务器**，不是仅在本机记一条备注；脱敏不保证移除所有私人信息，提交或分享导出包前仍应检查。

<a id="开发中会话模型与恢复" />

## 2.3.4 · 会话模型与恢复

以下功能从 **2.3.4** 起可用，适用于工作台、设计器、脚本、设置和场景助手；2.3.13 起请使用桌面界面。

每个对话保存自己的具体模型和思考档位，切回历史对话时沿用该对话的选择，不会因其他对话换模型而改变。新对话优先使用同账号已保存的最近一次明确模型选择，思考档位回到自动；尚无最近选择时，才用 AI 默认模型初始化。新规则不会改写全局用途与优选模型，也不再让对话持续跟随全局默认模型变化。

选择时核对完整模型系列、版本和连接名称，避免把同名的不同连接选混。已选模型被删除、停用或无法调用时，会保留选择并提示原因，不会悄悄换到另一个模型。打开菜单或查看旧对话本身不会改变新对话使用的最近模型；有历史但尚未保存模型身份的旧对话，会先尝试匹配最后实际使用的模型，不能确定时使用默认模型初始化。

新的选择用于后续请求，不会替换已经运行中的回合。模型不支持原思考档位时回到自动；“自动”和明确关闭思考是不同设置。历史包含图片时仍需核对目标模型的图片能力，不能靠换模型静默丢弃图片。切换可能使提示缓存失效，增加耗时和用量。

切到较小上下文窗口时，可能需要由目标模型分段压缩历史，这也会产生用量。压缩失败或取消会保留原历史；容量仍超限时不能继续正文请求，请按提示换模型、减少输入或手动压缩。恢复历史会话不会重新执行旧工具操作。

<a id="开发中批量修改设置与触发规则" />

## 2.3.4 · 批量修改设置与触发规则

以下功能从 **2.3.4** 起可用。

在设置或场景窗口中，明确要改的页面、场景和规则。例如：“把面板按钮大小改为 48，同时关闭按钮文字”。助手可一次提交多项已支持的设置；需要批准时，卡片逐项列出设置路径、标题及旧值到新值的变化，删除列表项会单独说明。查找、读取和定位页面本身不需要批准。

批准前若你或同步操作改变了相关设置，整批复核会拒绝写入，请让助手重新读取并生成变更。提交过程中某项失败或发生冲突时，后续项停止，**前面已保存的项不会自动回滚**。检查逐项结果，区分已保存、未变化、冲突、失败和未尝试；“已保存但应用失败”意味着值已经保存，仍需处理提示并核对实际效果。

触发规则也会核对批准时的目标和内容。批准期间删除、移动或修改了对应规则，或执行内容与预览不同，会停止不一致的写入；此前已完成的修改仍需检查。2.3.4 的完全控制包含列表删除时仍需本人确认；2.3.5 起按[完全控制的新范围](#235--完全控制与工具恢复)直接执行已启用的工具。助手仍不能替自己开启写入授权或更改审批方式。

已支持的密码或密钥类设置会向助手提供实际值，批准卡和回执也可能显示这些值；修改此类项目后，分享对话前请检查内容。

重新打开或切换历史对话，只显示旧记录中的设置链接，不会再次自动跳转到旧页面。尚未支持的设置仍需打开原界面手动修改；这里没有新增通用撤销，也不保证一次请求的所有修改都成功。

<a id="开发版窗口助手" />

## 2.3.2 · 窗口助手

以下功能从 **2.3.2** 起可用。

### 给设置与场景助手添加附件

设置窗口和场景、动作与触发管理窗口中的助手也提供「添加附件」和截图入口，可通过选择文件、粘贴或拖放补充问题材料。例如，询问某项设置时附上当前界面截图，或为触发规则附上需要匹配的文本样例。

附件沿用[设计器助手的数量、大小和类型限制](#给设计器助手添加附件)。发送前检查附件卡片；编辑已发送的消息时可保留或移除原附件，历史图片可显示缩略图。附件只补充对话材料，不会直接导入设置，也不会改变场景助手只绑定已有动作的范围。

### 查找和继续窗口中的历史会话

组合动作 / 公共子程序设计器、脚本编辑器、设置和场景助手的标题栏增加历史会话入口。会话按当前账号保存在本机，重启后可以续聊，旧版进程内临时对话不会自动成为可恢复历史。发送消息后会自动保存；打开列表可选择旧会话继续聊天，也可以新建会话。

- 设计器和脚本助手按当前编辑对象列出历史，不会混入其他动作的会话；组合动作与脚本助手的历史也分开。
- 设置和场景窗口共享一组窗口助手历史，可在其中找到此前的设置或触发规则对话；它与独立 AI 助手的工作区会话列表分开。
- **载入历史只恢复消息与模型上下文，不会把当前动作、脚本或设置回退到当时的内容。** 继续修改前，重新说明当前状态和要求。

未归档会话可以改名。归档会保留消息、附件和模型上下文，可切换到归档列表恢复；归档当前会话后，会进入新会话。删除则需确认，消息、模型上下文和对应附件无法恢复，删除当前会话后也会进入新会话。

「删除全部」包含当前范围内已归档的会话：设计器 / 脚本助手针对当前动作，设置 / 场景助手针对共享的全部窗口助手历史。确认前检查范围。

正在处理请求、导入附件或输入区仍有待发送附件时，不能切换或管理历史。先等待任务结束，并发送或移除待发送附件，再操作。

## 2.3.6 · 统一设置入口与助手范围

以下功能从 **2.3.6** 起可用。

设置 / 场景窗口助手、独立对话及外部 MCP 助手使用桌面设置中已开放的项目。告诉助手具体页面和设置名称，可先查找、读取，再修改已支持的项目；不支持或只读时，从回复中的设置卡片打开桌面页面，自己完成操作。网页不再提供另一套完整设置编辑页，入口见[桌面与网页设置](/v2/what's-new/tools-and-experience#236--桌面与网页设置入口)。

AI 服务连接与远程文件账号列表可供助手查询，但不能据此认定助手能新增、改写或删除其中的账号。连接、模型和密钥请在对应桌面设置页处理；已有动作的快捷键与快速运行等规则按触发管理流程设置。桌面没有开放的内部项目，也不会因为换到外部助手就变为可写。

回复中的设置卡片需要本人点击才打开页面；仅查看回复或恢复历史不会自动跳转。审批方式、批准前复核、逐项结果和部分保存不自动回滚的限制继续适用，详见[批量修改设置与触发规则](#234--批量修改设置与触发规则)。

## 2.3.7 · API 配置与外部助手授权

以下说明依据 **2.3.7 发布快照**，版本是否开放下载以[官网版本记录](https://getquicker.net/V2/Versions)为准。

对话内的「配置 API」恢复为可直接编辑服务和模型的弹窗。配置步骤、自动保存及测试选择的区别见[统一 AI 服务与模型设置](/v2/what's-new/ai-services-and-models#237--api-配置弹窗)。这个本人操作的入口不改变上方所说的助手服务列表只读范围。

已配置密钥但模型不可用时，模型菜单会区分「待确认工具调用」「不支持工具调用」、连接停用、模型停用和缺少密钥等原因。Agent 需要支持工具调用的模型；能力未知时先在配置界面测试或核实，再设置支持，明确不支持时选择其他模型。不要把所有不可用状态都当成需要重新输入 Key，也不要仅凭保存了 Key 就认定模型可用于 Agent。

请求批准模式下，Claude 桌面内置的 Claude Code 若只改变同一安装布局中的版本或构建目录，可沿用此前的 MCP 同意；原有包含构建目录的授权也会按同一规则识别。此例外限定于对应的 Claude 安装布局，不适用于任意程序的哈希目录。改变安装位置或程序名称仍需按实际客户端重新检查；撤销方式和「允许 MCP 写入」继续分别控制。

## 2.3.7 · 保存已有动作

在独立 AI 对话中通过 `@` 引用已有动作并说明修改要求。打开尚无旧暂存副本的动作时，不再额外建立同名暂存动作；同一项目中的聊天复用该动作的工作内容。其他项目及图形编辑器尚未实时共用这份工作内容。

「保存」会固定本次内容、校验并按权限提交原动作，无需另行要求「写回原动作」。成功提交后，面板和快捷键使用已保存的新内容；开启完全控制时可直接提交，请求批准时仍按提示确认。批准前请检查完整修改，其中可能包含同项目其他聊天留下的内容。保存不会绕过只读限制，也不等于已运行验证。

原动作或确认中的工作内容又被修改时，过期的保存会被拒绝，当前修改保留。先备份需要的内容，再重新读取最新动作并合并，不能整份覆盖其他修改。保存前会保护旧版本；若提示已保存但新历史记录失败，应核对原动作及历史，不要把提醒当成提交失败。

旧暂存数据不会批量迁移或删除。已经存在的编辑副本由助手在保存时接续写回；新建动作仍先保存到暂存区，检查后使用「保留到场景」。正式提交后的内容按正式动作规则参与同步，未提交工作内容不因多个聊天共用就自动同步到其他设备。升级说明见[升级与回退](/v2/migration/upgrade-and-rollback#237--贴图主题与-ai-保存)。

## 2.3.5 · 完全控制与工具恢复

从 **2.3.5** 起，选择「完全控制」即授权助手直接执行已启用的工具，包括运行动作、写回修改、删除、命令和桌面操作，不再按工具或参数逐次确认。内置桌面 Agent 的文件工具也可按当前请求访问工作区外的磁盘路径，仍受当前 Windows 用户权限约束；此能力不适用于外部 MCP。需要逐次确认时，选择「请求批准」。

MCP 会继承全局 Agent 的完全控制；Agent 或 MCP 任一选择完全控制时，连接和已启用的工具直接执行。MCP 默认关闭，编写动作仍需启用「允许 MCP 写入」。完全控制不会自动启用桌面操作，也不会跳过参数校验、动作版本检查或冲突保护，或让未开放的功能变为可用。

对外部 MCP，「完全控制」改变的是审批方式，文件访问范围仍限制在 Quicker 工作区、已打开的动作槽位及只读逻辑挂载，不能据此访问任意本机路径。

2.3.4 的普通设置中已隐藏 Computer Use 开关；已有插件配置仍保留。不能仅凭选择完全控制认定桌面操作已启用。

普通工具调用失败后，助手可以读取错误、修正参数并继续尝试；这不代表失败操作已完成，也不等于服务请求失败后会自动换模型。检查最终保存结果与实际行为。权限切换或取消请求时，旧确认窗口不再使请求持续停住。
