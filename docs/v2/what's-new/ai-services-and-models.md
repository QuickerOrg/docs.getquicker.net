# 统一 AI 服务与模型设置

Quicker 1.x 的 AI 参数主要分散在具体动作或功能中。V2 新增统一的 AI 设置入口，把“连接哪个服务”“使用哪个模型”和“某项功能优先选择哪些模型”分开管理。

## 打开 AI 设置

打开 Quicker 设置，在“AI”分类中选择：

- **AI 服务**：管理服务地址、协议、凭据、代理、超时和可用模型；
- **用途与模型**：为不同用途设置按顺序尝试的候选模型。

当前内置服务模板包括 OpenAI、DeepSeek、阿里云百炼、火山方舟、智谱 AI、Moonshot AI、MiniMax、百度千帆和硅基流动等。

也可以连接 Ollama、LM Studio 等本机服务，或填写兼容 OpenAI Chat Completions、OpenAI Responses 协议的自定义接口。

## 服务连接与模型分开管理

一个 AI 服务连接负责保存供应商、协议、API 地址、认证方式、代理和超时等信息。连接建立后，可以从服务获取模型列表，也可以手工填写 API 模型 ID。

模型可以单独启用、停用、测试和修改显示名称。Quicker 还会记录模型是否支持流式输出、工具调用、结构化输出和图片输入等能力。

能力状态用于帮助选择模型，并不能替代服务商的实际接口说明。自定义或新发布模型的能力可能显示为未知，可以在确认后手工调整。

## 按用途设置候选模型

V2 可以为日常文本处理与翻译、图片理解、Agent 与工具调用等用途设置候选模型顺序，也可以建立基于这些类型的自定义用途。

调用某项 AI 能力时，Quicker 会按照该用途的候选顺序寻找可用模型。连接被停用、凭据缺失或模型能力不符合要求时，该模型不会被当作正常候选使用。

“用此模型对话”可以直接测试当前模型，但不会修改用途的候选顺序。

## 凭据如何保存

API Key 不会直接写入普通 AI 设置 JSON。Quicker 使用 Windows DPAPI，以当前 Windows 用户身份加密后保存到本机独立凭据文件。

因此，复制设置文件到另一台电脑或另一个 Windows 用户后，原凭据通常不能解密。需要在目标环境重新填写 API Key。

凭据不会写入动作定义，也不会随动作分享。调用远程服务时，输入内容仍会发送给所选服务商；费用、日志、数据保留和隐私政策由对应服务商决定。

## 当前功能边界

统一设置页提供公共的连接、模型和用途配置，但不表示所有历史 AI 入口已经在同一版本中完成迁移。具体功能是否使用这里的候选模型，应以该功能页面和实际界面为准。

部分 Agent、Web 动作设计器和动作助手仍可能处于开发或发布门控状态。看到“Agent 与工具调用”用途，不等同于当前版本已经开放全部相关界面。

配置正式动作前，建议先执行连接测试和模型测试，并使用不含敏感信息的样例确认协议、模型 ID 和能力设置正确。
