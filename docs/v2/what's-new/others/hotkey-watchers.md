# 热键联动

热键联动用于监听一个快捷键，或依次按下的两段快捷键，再执行指定操作。例如先按 `Ctrl+K`，再按 `C` 执行一个动作。

2.x 保留了 1.x 的单段、两段序列、延迟时间和设备限制，同时让热键联动进入统一的场景规则体系。

## 按场景组织按键序列

可以在“场景与动作管理 → 键盘触发 → 热键联动”中，为全局、程序、标题子场景或网址场景分别配置规则。

普通程序会按“当前程序 → 全局”查找；浏览器和网址还会经过浏览器通用场景。这样可以在不同应用中复用同一段前缀键，而不必把所有规则堆在一个带进程过滤条件的全局列表中。

原有全局规则仍保留进程白名单、黑名单、限定主机和延迟时间。普通场景由场景本身限定范围，编辑时不再要求重复填写进程名。

## 同序列覆盖上级规则

热键联动使用“第一段快捷键 + 可选第二段快捷键”作为规则键。

- 当前场景没有同序列规则：继续使用上级规则；
- 当前场景存在同序列规则：使用当前场景规则；
- 当前场景的同序列规则被停用：不再回退上级同序列；
- 删除本地同序列规则：恢复继承。

管理页默认只显示本地规则。勾选“显示继承的规则”后，可以看到按键序列、来源、操作类型、摘要和状态，并把继承规则复制到本场景再编辑。

## 输入过程更适应场景变化

两段热键属于短暂键盘输入。2.x 不会把开始输入时的物理进程长期固定为整个序列的唯一依据，也不会因为窗口、标题或网址变化就机械取消已经按下的第一段。

后续按键会读取当时的当前场景和规则。这使需要切换窗口后完成第二段的操作更自然，同时避免继续使用已经过期的规则对象。

## 管理界面改进

新版列表支持：

- 新增、编辑、启停和删除；
- `Ctrl` / `Shift` 多选及批量删除；
- 显示继承规则及真实来源；
- 复制继承规则到当前场景；
- 统一显示操作类型、摘要、延迟和失效状态。

编辑窗口仍可以设置第一段、可选第二段、说明、延迟和限定主机。已有数据能够读取但当前版本不能编辑的操作，会保留原内容并显示状态提示。

## 从 1.x 升级时需要注意

- 原有全局热键联动规则和进程过滤条件会继续保留；
- 不会自动把旧白名单规则拆分为程序或网址场景；
- 停用本地同序列规则会屏蔽上级规则，删除本地规则才恢复继承；
- 两段序列应避免与动作快捷键、扩展热键或其它程序的系统快捷键冲突；
- 在浏览器网址场景中，建议实际切换几个标签页确认规则来源符合预期。
