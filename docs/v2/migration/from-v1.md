# 从 V1 迁移到 V2

:::caution[Preview · 仅专业版]
当前 V2 是 **Preview 体验版**，仅面向专业版用户。免费版数据迁移仍在开发，免费账号目前无法登录 2.0。不建议用它替换无法中断的 1.x 关键环境。体验前请先读 [体验前必读](/important-notice)。
:::

Quicker 2.0 尽量兼容 1.x 的动作和组合动作模块，但存储、编辑器、表达式和执行管道已经换代。两代**不能同时安装**（浏览器扩展会冲突）。迁移是一份可执行清单，不是「两套程序并行、只是别交叉改动作」。

## 迁移清单

### 1. 在 1.x 里同步并导出备份

1. 在最后使用的 1.x 客户端执行一次同步。
2. 导出特别重要或难以重建的动作、公共子程序。
3. 另外保留一份 1.x 数据备份（不要只依赖本机那个正在用的目录）。
4. 记下常用动作页、复杂触发规则，以及依赖第三方软件、浏览器扩展、脚本环境或本机文件的动作。
5. 对多线程、循环、等待、C# 代码和复杂表达式动作，先做测试副本。
6. 关闭其它设备上的 Quicker，避免迁移时还在写入旧数据。

### 2. 卸载 1.x

浏览器扩展会冲突，**不要把 1.x 和 V2 装在同一台电脑上同时使用**。备份确认无误后，先卸载 1.x，再装 V2。

### 3. 从官网 V2 页安装

打开 [https://getquicker.net/V2](https://getquicker.net/V2) 下载安装包。不要使用 [https://getquicker.net/Download](https://getquicker.net/Download)，那个页面目前提供的是 1.x。

系统要求和首次启动见 [安装 Quicker V2](/v2/install/windows.md)。

### 4. 首次登录会分叉数据

用专业版账号登录。首次登录会以「数据分叉」的方式迁入当前账号数据，之后 1.x 与 V2 **各自独立**，不是双向镜像。

- 之后在 1.x 里改的内容，不会自动进入 V2。
- V2 里的新面板分组、场景位置和新版动作参数，也无法完整写回 1.x。
- V2 不会把旧的 `quicker.db` 当作日常库继续写入。

背景见 [数据存储与同步变化](/v2/what's-new/data-and-sync.md)。

### 5. 核对动作、触发和子程序

等首次同步完成后再改面板。建议按这个顺序验证：

1. 先运行不修改外部数据的简单动作，确认变量、表达式和基本步骤。
2. 再验证文件写入、网络请求、软件控制等会影响外部状态的模块。
3. 最后验证并行分支、循环、等待、子程序和长时间运行的动作。
4. 核对常用触发规则（快捷键、轮盘、手势、文本指令等）和公共子程序。
5. 需要继续编辑的旧版组合动作，迁成新版组合动作；无法识别的步骤应保留为不可编辑占位，不应在保存其它内容时静默丢失。
6. 启用 QkEval 后，失败不会回退到旧表达式引擎；复杂表达式先复制动作测试。

旧版组合动作可以兼容运行和查看，但不能继续编辑。模块参数以 [模块参考](/v2/xaction/modules) 为准。

### 6. 回退 = 重装 1.x

需要回到 1.x 时：

1. 卸载 V2。
2. **重新安装 1.x**。
3. 使用迁移前的 1.x 备份或导出文件恢复；不要把 V2 数据目录覆盖到 1.x。

两代的模型、同步状态和账号目录都不同，不能靠替换 `quicker.db` 在两边来回切。

## 组合动作还要重点看

大多数已有模块在 2.0 中继续保留。需要继续维护的复杂动作，先识别再逐步验证，不要在尚未验证时覆盖唯一可用的正式动作。

- 动作存储和使用位置分离，删除动作本体与从面板移除位置的影响不同；
- 启用 QkEval 后，不再回退到旧表达式引擎；
- 旧版只读动作不支持会暴露内部结构的断点和单步调试；
- 外部组件不响应取消时，并行分支可能不能立即结束；
- .NET 10、64 位进程和第三方程序集兼容性需要单独检查。

详细背景见 [动作存储、执行与调试](/v2/what's-new/actions)、[组合动作执行与调试变化](/v2/what's-new/actions/xaction-steps) 和 [运行平台与兼容性](/v2/what's-new/platform-and-compatibility)。
