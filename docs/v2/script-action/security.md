本文说明 **2.3.23 起**的脚本动作行为。使用旧版本时，仍可能遇到原有的能力限制和授权确认；升级和回退见[升级与回退](../migration/upgrade-and-rollback.md#script-and-settings-2323)。

## 1. 一句话概括

- 脚本可直接使用文件、网络、进程等 .NET 类型，并继续使用 `qk` API 操作 Quicker 和桌面。
- 脚本在 **Quicker 进程内、以 Quicker 的权限执行**，没有文件、网络或进程隔离。
- 自建、安装、导入和粘贴的脚本动作运行时，**均不再按来源或能力逐项确认**。请先核对源码和动作来源再运行。
- AI 助手临时执行代码仍遵循助手的审批模式；允许执行一次代码，不代表操作可以撤销。

## 2. .NET 能力与执行范围

脚本与组合动作共享 .NET 类型环境。可以使用 `File`、`Directory`、`HttpClient`、`Process` 等类型，也可以继续通过 `qk.Files`、`qk.Http`、`qk.Process` 等 API 完成任务。可用语法、类型解析和迁移方式见[语言与脚本结构](./language.md)。

`qk` API 仍有参数检查、次数和大小限额、目标窗口限制及资源清理规则。这些规则只约束对应 API，**不能约束直接调用 .NET 的代码**。代码可能读写文件、发送网络请求、启动程序或影响 Quicker 自身。

脚本动作不是操作系统沙箱。不要因为编辑器“检查通过”或动作来自分享平台，就认为它不会修改或泄露数据。

## 3. 运行前的确认

| 场景 | 2.3.23 起的行为 |
|---|---|
| 运行自己编写或 AI 帮写后保存的脚本动作 | 不做逐能力确认 |
| 从动作库安装、更新，或从文件、剪贴板导入后运行 | 同样不做逐能力确认 |
| 在脚本编辑器中点击运行或调试 | 真实执行当前源码，不是预览，也不会自动回滚 |
| AI 助手临时执行代码 | 作为“执行代码”操作，按当前助手审批模式决定是否确认 |

旧版的逐能力授予记录不再决定新版脚本能否运行，也无需通过删除再安装动作来重置授权。希望阻止某个脚本执行时，应停止运行并停用其触发规则，或移除该动作。

## 4. 停止与清理

动作停止和超时会通知解释器及支持取消的 `qk` API。停止后的 `finally` 仍只允许有限清理，例如释放已按住的键、恢复本次剪贴板、关闭本次进度窗口或写日志；继续调用普通操作可能被拒绝。

**直接调用阻塞的 .NET 方法不保证能立即停止。** 已发出的请求、已启动的程序和已完成的文件修改，也不会因停止动作而自动撤销。不要用无限等待或阻塞调用替代可取消的 `qk` 操作；停止后仍有外部操作时，应在对应程序中核对结果。

完整的超时、取消与句柄规则见[运行上下文与生命周期](./runtime.md)，API 限额见[运行限额](./limits.md)。

## 5. 运行他人或 AI 编写的脚本前

先确认它将读取什么、修改什么、把内容发送到哪里。尤其留意文件删除和覆盖、网络上传、键盘监听、启动外部程序、结束进程及电源操作。涉及重要文件时，先备份并在测试数据上运行。

AI 生成的代码同样需要检查。引用网页、文件或聊天内容可能把不可信指令带入编写过程；不要依赖能力弹窗或“新增高风险能力”提醒发现问题。脚本绘制的界面也可能仿冒登录窗口，请勿输入其他账号的密码。

## 6. 分享与版本兼容

分享前写清用途、外部依赖、数据修改和网络访问范围，并检查关键路径。分享脚本时不再要求通过旧的 `qk` 能力识别规则；是否使用某个 .NET 类型，不再构成原先的能力授权门槛。

分享平台仍记录客户端版本，旧客户端可能提示升级。使用新开放的 .NET 能力的脚本，在 2.3.22 及更早版本可能检查失败或无法运行；需要兼容时请保留旧版副本，见[分享与版本兼容](./sharing.md)。

## 7. API 兼容

`qk` API 仍随版本演进。个别成员调整时，按编辑器“检查”的提示改写。判断错误原因请使用错误码，不要解析错误消息文字，详见[常见问题](./troubleshooting.md)。
