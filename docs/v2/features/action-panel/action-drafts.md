# 本机动作暂存区

Quicker V2 新增了本机动作暂存区。它适合保存尚未确定放置位置、仍需试验，或暂时不希望进入正式动作库的动作。

1.x 中，新动作通常需要先放到动作页才能继续编辑和运行。V2 的暂存动作可以先独立存在，确认可用后再放入新面板场景。

## 打开暂存区

打开新版主窗口，点左侧导航里的「暂存区」图标（收件箱，在「动作」下方）。右侧内容会换成暂存列表。这里列出的动作与当前账号关联，但只保存在这台电脑上。

暂存区共用新版主窗口的搜索入口。输入动作名称后，可以用方向键选择结果，按 `Enter` 试运行。

2.2.0 起，暂存区顶部提供 **新建动作** 和 **用 AI 写**。用 AI 写出的动作会先进入暂存区预览；AI 创建或修改暂存动作后，暂存区会自动刷新。该功能仍在改进中，生成内容需要人工检查、试运行和调试。

在 2.3.0 中，如果剪贴板中是 Quicker 分享动作链接，点击暂存区右上角的 **＋**，菜单会同时显示「创建动作」和「安装剪贴板中的分享动作」。选择安装后仍会显示正常的动作确认信息，确认完成后动作直接进入暂存区，不会先注册为正式动作。

剪贴板不是有效分享链接时，不会提供安装项。链接无法读取或动作要求更高版本时，安装不能继续；可以改为创建本机动作。

:::note[2.3.1 起的变化]
以下行为从 **2.3.1** 起可用：

- 点击 **＋** 后，先选择「创建组合动作」或「创建脚本动作」，再进入对应编辑器；没有分享链接时也会显示这两个选项。剪贴板有有效分享链接时，菜单还会提供「安装剪贴板中的分享动作」。
- 从暂存区启动运行或调试时，会先收起主面板，再运行最近保存的内容，便于操作目标软件。

创建与试运行仍只使用本机暂存项，不会因此加入正式动作库或开启云同步。
:::

## 可以对暂存动作做什么

右键暂存动作可以执行以下操作：

- 试运行最近保存的版本；
- 以调试模式运行；
- 打开动作编辑器继续修改；
- 悬浮动作，继续以暂存身份运行和编辑；
- 复制动作定义，粘贴到动作面板或编辑器；
- 查看动作信息和本机版本历史；
- 将动作正式保留到某个场景；
- 丢弃动作及其全部暂存版本。

暂存动作保存时会建立本机版本记录。需要撤销较大的修改时，可以打开“版本历史”，选择以前的版本恢复。

<a id="开发中编辑分享动作的暂存项" />

### 编辑分享动作的暂存项

以下修复从 **2.3.3** 起生效。

安装分享动作到暂存区后，打开编辑器会先读取其实际来源内容，并沿用来源权限。可编辑的动作可以修改并保存到暂存区；只读动作以只读方式打开，不能通过暂存区绕过限制。允许编辑但禁止再次分享到动作库的动作，也继续保留该分享限制。

来源读取或下载失败时会提示原因，不会用空动作代替原内容供你保存。请先处理网络或来源问题，再重新打开。没有修改实际动作内容时，保存仍保留来源引用；保存暂存项不会直接改写已有正式动作。

<a id="开发版从文件导入与导出" />

### 从文件导入与导出

:::note[适用范围]
以下文件操作从 **2.3.1** 起可用。
:::

需要在另一台电脑继续试用、保留一份动作文件，或删除暂存项前保存内容时，可以使用文件导入导出：

1. **导出**：先保存编辑器中的修改，右键暂存动作，选择 **导出动作**，保存为 `.v2.json` 文件。导出的是该暂存项最近保存的动作定义。
2. **导入**：在暂存区点击 **＋ → 从文件导入动作…**，选择 Quicker 导出的 `.v2.json`、`.v1.json` 或可识别的动作 JSON 文件。导入成功后，动作会出现在本机暂存列表中。
3. 检查内容并试运行；新动作确认可用后，再选择 **保留到场景**。

导入不会覆盖本机已有的同标识动作：正式动作库或暂存区已有该标识时，会改用新标识。导入项会清除分享来源，不能凭这个文件自动更新原分享或写回原动作。

动作文件不包含暂存分组和本机版本历史，也不会开启云同步；需要多份历史内容时，应分别恢复并导出需要的版本。文件过大或内容无法识别时会提示导入失败。来自文件的脚本动作仍按外部导入处理，运行前遵循[脚本动作授权规则](/v2/features/script-actions/security)。

<a id="开发版手动备份和版本说明" />

### 手动备份和版本说明

:::note[适用范围]
以下功能从 **2.3.1** 起可用。
:::

准备进行较大修改前，可以保留一个有说明的版本：

1. 先在编辑器保存需要备份的内容。备份取的是已保存版本，不包含尚未保存的编辑。
2. 右键暂存动作，选择 **创建备份…**，打开版本历史。
3. 选中需要保留的版本，填写说明，并勾选 **保留为手动备份（不自动裁剪）**。
4. 点击 **保存说明 / 备份**。只填写说明、勾选后关闭窗口不会保存这些设置。

也可直接从 **版本历史** 修改某个已有版本的说明，或筛选查看手动备份。标记备份不会修改动作内容，也不会增加一个新的内容版本；普通历史保留最近 30 个版本，手动备份不参与这项自动裁剪。取消备份保护后，较旧版本可能立即被裁剪。

选择旧版本并点击 **恢复选中** 后，会以旧内容生成一个新版本，恢复前的已保存内容仍保留在历史中。如果当前动作或版本说明已被其它窗口修改，请刷新后重新核对。

手动备份仍只属于本机暂存项，不是云端副本。丢弃、全部删除，或写回成功后移除暂存项时，其历史和手动备份也会一起删除。

超过 30 天没有活动的暂存动作会显示清理提示，但 Quicker 不会据此自动删除。确认不再需要后，应由用户手工丢弃。

## 新动作与已有动作的编辑副本

:::note[2.3.7 保存流程变化]
以下编辑副本与单独写回的流程描述 2.3.6 及更早版本。2.3.7 中，AI 打开尚无旧暂存副本的已有动作不再额外创建暂存项，同一项目聊天复用工作内容，「保存」按权限提交原动作。旧暂存数据仍保留，助手保存旧编辑副本时接续写回；新建、导入和安装的暂存动作仍需「保留到场景」。详见[保存已有动作](/v2/features/ai-and-agent#237--保存已有动作)。
:::

暂存区既可以保存新动作，也可以保存 AI 修改已有正式动作时建立的编辑副本。两者完成修改后的操作不同：

| 暂存内容 | 确认可用后的操作 | 正式生效前 |
| --- | --- | --- |
| 新建或安装的动作 | **保留到场景** | 只在本机暂存区保存和试用 |
| 已有正式动作的编辑副本 | **写回原动作** | 原动作的面板入口和热键继续运行原内容 |

编辑副本也可以保存本机版本、试运行和调试。选择 **写回原动作** 并确认后，Quicker 用副本内容覆盖原动作；通常会在写回成功后移除该暂存项。

在 2.2.24 中，如果原动作在建立副本后又被修改，写回会被拒绝，避免覆盖较新的内容。该版本不会自动合并：先保留需要的修改，再丢弃旧副本、重新打开最新原动作继续处理。如果确认写回期间暂存副本又发生变化，也需要检查最新内容并重新确认。2.2.25 起新增的合并与冲突处理见[下文](#原动作已变化时处理冲突)。

丢弃编辑副本不会删除它对应的正式动作，但会删除副本及其本机版本历史。

## 保留为正式动作

选择“保留到场景”，再指定目标场景和分组，即可把暂存动作写入正式动作库，并在目标位置增加入口。手动新建、导入安装和 AI 创建的暂存动作都使用这条路径正式化。

也可以把暂存动作直接拖到新面板或“场景与动作管理”中的目标位置。写入成功后，原暂存项会被移除。

正式化会继续使用暂存动作的标识。动作进入正式动作库后，才能被普通快捷键、轮盘、手势等规则稳定引用，并按正式动作规则参与同步。

<a id="开发版原动作已变化时处理冲突" />

## 原动作已变化时处理冲突

:::note[适用范围]
以下合并与冲突处理从 2.2.25 起可用，针对暂存编辑副本的写回。2.2.24 不会自动合并两边的修改。2.3.7 新打开已有动作的保存冲突处理见[保存已有动作](/v2/features/ai-and-agent#237--保存已有动作)。
:::

独立 AI 对话修改已安装的正式动作时，会使用它的暂存编辑副本。若正式动作随后也被修改，在「写回原动作」时会比较原始内容、当前正式动作和暂存副本，尝试保留双方不冲突的修改。

程序中的步骤、变量、子程序和表达式可能互相依赖；双方都修改了程序内容时，不能仅因改了不同步骤就当作可以自动拼接。缺少可靠原始内容的旧草稿，也不会猜测哪一边才应保留。有冲突时，写回会停止，两份修改都保留。

出现「让 AI 协助合并」时，可以主动点击并说明希望保留的行为。助手会读取差异、整理候选内容；不明确的取舍仍需本人决定。**合并结果先保存到暂存副本**，重新检查并试运行后，再确认写回原动作。仅写回失败不会自动发送合并请求。

2.3.1 起开启 **完全控制** 时，助手可按当前请求直接应用合并后的修改，不再逐次等待写回确认；版本校验和冲突保护仍保留。其它审批方式仍需确认，详见 [AI 写回与历史说明](/v2/features/ai-and-agent#动作保存与对话入口)。

如果合并期间原动作或草稿又变了，需要重新读取差异，不能沿用过期的选择。不要为了消除提示而直接丢弃仍需要的草稿。

<a id="开发中外部助手恢复编辑副本" />

### 2.3.4 · 外部助手恢复编辑副本

以下修正从 **2.3.4** 起可用，适用于内置及通过 MCP 连接的动作编写助手。

编辑期间，草稿被保留为正式动作、删除后重建，或其他会话保存了新内容时，旧编辑副本不能直接写回新的存储对象。助手会保留可读取的旧内容；身份失效时按只读副本处理，可先保留完整备份，再刷新或重新打开。

恢复后以 **最新已保存内容** 为基底，旧备份用于比较差异，并重新应用本次任务仍需要的修改，不应整份覆盖最新动作。原动作已不存在或暂时无法读取时，不能继续保存回原目标；可先备份，处理故障后重试，或明确新建暂存动作并迁入所需内容。刷新失败时仍应保留已完成备份，并检查实际返回的路径。

外部助手自己的项目目录与 Quicker 动作编辑区是不同位置。助手返回的动作槽位和备份路径应通过 Quicker 的文件工具读取，不要拼到外部项目目录中直接修改。恢复、备份或打开预览都不等于已经保存，更不等于已写回正式动作；最终仍需检查保存位置、版本和写回结果。

## 与正式动作和同步的区别

暂存内容不会作为独立的正式动作出现在普通动作选择器和触发规则选择器中。已有动作的编辑副本不会替换选择器中的原动作；只有完成写回，原动作才使用修改后的内容。暂存区的试运行只执行该暂存项最近保存的内容，不会临时建立正式动作引用。

暂存动作、暂存分组和本机版本历史保存在当前账号的本机数据中，不参与云同步。切换账号后会看到该账号自己的暂存区；换一台电脑也不会自动出现这里的动作。

如果希望跨设备使用，新暂存动作需先保留到正式场景，已有动作的编辑副本需先写回原动作，再等待正式动作同步完成。

## 删除和恢复边界

“丢弃”会删除该暂存动作及其本机版本历史。“全部删除”会清空当前账号的整个暂存区。这些操作不会把内容移入正式动作回收站，确认后无法从暂存区恢复。

暂存内容尚未正式保存或写回时没有云端副本。删除前如果仍可能需要，请先复制需要保留的内容；新暂存动作也可以先保留到一个临时场景。
