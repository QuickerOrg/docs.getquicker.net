# 动作快捷键

动作快捷键用于把系统级组合键直接绑定到一个 Quicker 动作或操作。它不同于“功能快捷键”：功能快捷键控制显示面板、搜索等 Quicker 内置功能，动作快捷键执行用户配置的内容。

1.x 的动作快捷键集中保存在全局列表中，主要通过进程白名单和黑名单限制范围。2.x 让动作快捷键真正成为场景规则，并改进了前台切换时的注册和诊断方式。

## 按场景设置快捷键

2.x 可以在“场景与动作管理 → 键盘触发 → 动作快捷键”中，为以下上下文分别设置规则：

- 全局场景；
- 普通程序；
- 程序路径、窗口标题或窗口类子场景；
- 浏览器程序和浏览器通用场景；
- 网址场景。

例如，可以让 `Ctrl+Alt+S` 在全局运行搜索动作，在浏览器中保存网页，在图片编辑器中运行导出动作。规则归属于场景本身，不需要为每条普通场景规则重复填写进程名。

原有全局规则仍保留进程白名单和黑名单，方便兼容 1.x 的配置方式。普通场景的编辑器会隐藏这些字段，以免与场景作用域重复。

## 同键规则的继承与覆盖

运行时会按最具体场景到全局的顺序查找当前快捷键。

当前层只要存在相同快捷键的本地规则，就取得这个快捷键的控制权：

- 本地规则启用：使用本地规则；
- 本地同键规则全部停用：不触发，也不回退上级；
- 当前层没有定义该键：继续查找父场景或全局规则；
- 删除当前层最后一条同键规则：恢复上级继承。

如果同一层为一个快捷键配置了多条动作，2.x 继续使用动作选择菜单，不会强制合并或丢弃已有规则。

管理页默认只显示本场景规则。勾选“显示继承的规则”后，可以查看规则的真实来源，并将继承规则复制到本场景再修改。

## 前台切换时更稳定

2.x 只为当前前台场景维护需要的系统快捷键，并按差异增加或释放按键，减少无关快捷键被 Quicker 长期占用。

前台窗口变化时，不再先无条件释放全部动作快捷键再等待新场景完成识别。对于新旧场景共同使用的按键，系统注册会尽量保持不动；新增按键先注册，旧场景独有按键再释放。

收到快捷键消息后，Quicker 还会重新核对当前窗口、网址和最新规则，而不是直接执行注册时缓存的旧动作。因此，快速切换程序、浏览器标签或 WPS 内部文档时，更不容易执行上一个场景的内容。

## 状态和冲突更容易发现

新版管理页会分别显示：

- 快捷键和操作摘要；
- 规则来源；
- 是否引用了已删除或不可用的动作；
- 当前版本是否可以编辑该操作；
- 最近一次 Windows 快捷键注册失败状态。

注册失败不会在每次自动切换场景时反复弹窗。可以在管理页点击“刷新状态”集中检查。

全局规则仍支持按生效进程分组；规则列表支持多选和批量删除。免费版数量限制按账号中全部场景的动作快捷键总数计算，已有或同步得到的超限规则会保留，只限制继续主动新增。

## 从 1.x 升级时需要注意

- 原有动作快捷键继续保存在全局场景，并保留白名单、黑名单和等待抬键设置；
- 不会自动把旧进程过滤规则拆成多个程序场景；需要时可以在对应场景中新建规则；
- 本地停用同键规则会屏蔽上级规则；要恢复继承，应删除本地同键规则；
- 桌面、任务栏和普通资源管理器在 2.x 中是不同逻辑场景，建议分别检查；
- 浏览器网址快捷键按“网址 → 当前浏览器 → 浏览器通用场景 → 全局”继承；
- 如果某个快捷键没有响应，先在管理页查看状态，再检查是否与其它程序或 Quicker 功能快捷键冲突。
