# 从 V1 迁移到 V2

Quicker 2.0 尽量兼容 1.x 的动作和组合动作模块，但动作存储、编辑器、表达式引擎、执行管道和调试能力已经发生变化。迁移的重点不是重新制作所有动作，而是先识别仍需维护的复杂动作，再逐步验证和替换。

## 迁移前

1. 保留仍在使用的 1.x 数据和可恢复备份。
2. 记录依赖第三方软件、浏览器扩展、脚本运行环境或本机文件的动作。
3. 对多线程、循环、等待、C# 代码和复杂表达式动作，先制作测试副本。
4. 不要在尚未验证时直接覆盖唯一可用的正式动作。

## 组合动作

大多数已有模块在 2.0 中继续保留，主要变化是增加模块、参数和新的执行/调试能力。可以通过[模块参考](/v2/xaction/modules)核对当前模块定义；页面中的参数表来自 2.0 程序导出的元数据，旧使用说明则作为兼容参考保留。

旧版组合动作可以兼容运行和查看，但需要继续编辑的动作应迁移为新版组合动作。无法识别的步骤应保留为不可编辑占位，不应在保存其它内容时静默丢失。

## 建议验证顺序

1. 先运行不修改外部数据的简单动作，确认变量、表达式和基本步骤。
2. 再验证文件写入、网络请求、软件控制等会影响外部状态的模块。
3. 最后验证并行分支、循环、等待、子程序和长时间运行的动作。
4. 使用新版调试功能观察失败步骤、变量和输出，再判断是兼容问题、环境问题还是动作自身问题。

## 需要重点检查的变化

- 动作存储和使用位置分离，删除动作本体与从面板移除位置的影响不同；
- 启用 QkEval 后，不再回退到旧表达式引擎；
- 旧版只读动作不支持会暴露内部结构的断点和单步调试；
- 外部组件不响应取消时，并行分支可能不能立即结束；
- .NET 10、64 位进程和第三方程序集兼容性需要单独检查。

详细背景见[动作存储、执行与调试](/v2/what's-new/actions)、[组合动作执行与调试变化](/v2/what's-new/actions/xaction-steps)和[运行平台与兼容性](/v2/what's-new/platform-and-compatibility)。
