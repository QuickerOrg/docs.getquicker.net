先完成[安装与首次启用](./install-and-manage.md)，保持 Quicker 和目标软件运行。

## 确认连接

打开 **Quicker 设置 → 软件连接**。上方显示本机服务，软件列表显示连接数；可筛选软件或按名称排序。软件已列出不代表已经安装 Bridge，本机服务正在运行也不代表宿主已经连接。

选择软件查看连接状态，使用 **刷新状态**。列表的连接诊断入口可以查看实例、宿主和 Bridge 版本、当前文档摘要，并提供 **复制诊断信息**。未打开文档时摘要可能为空，这与连接断开不同。

点击 **打开命令工具**，选择要操作的在线实例。核对软件版本及文档摘要；可精确区分进程的软件还会显示 PID。有多个同名会话时，不要只凭窗口标题判断。

## 先运行一个不修改文件的命令

1. 点击 **刷新实例**，选择目标实例，再 **刷新命令**。
2. 筛选 `bridge.ping`，选中该命令。
3. 参数使用空 JSON 对象：`{}`。
4. 点击 **立即调用**，查看结果。正常应收到成功响应及 `pong: true`；版本、文档上下文等附加字段随宿主而异。

`bridge.ping` 不修改模型或文件。它验证当前会话能响应，但不证明所有编辑、脚本或导出命令都可在当前文档中执行。

命令工具通过 `command.list` 获取**当前所选实例**实际支持的命令。升级 Bridge 或切换实例后应刷新目录，不要假定另一个软件或版本具有同名能力。

## 选择命令与填写参数

按命令名、标题或分类筛选。选择命令后先阅读说明和参数模板，再调整参数。脚本、保存、导出、删除或模型修改命令可能有副作用，应先在副本中验证。

参数必须是合法的 JSON **对象**，不是一段脚本、数组或带注释的文本。字符串使用双引号，不在最后一个字段后留逗号。Windows 路径中的反斜杠需要转义，例如：

```json
{
  "path": "C:\\Work\\example.txt"
}
```

此处只演示路径写法；实际字段以所选命令模板为准。空对象 `{}`、空字符串和 `null` 含义不同，尤其可选属性不能随意填入 `0` 或空文本，否则可能改写当前值。

## 立即调用与生成动作

**立即调用**发送到工具中显式选中的在线实例，结果显示在工具内。工具获得焦点不会让这次调用改投其他软件。

**生成动作**将当前命令及参数转换成动作并复制到剪贴板，可粘贴到 Quicker 面板。常用命令可能生成可视化字段，其他命令使用自定义命令名与 JSON 参数。生成后查看步骤与输出变量，再运行。

**动作不会保存工具窗口选择的临时 session。** 运行时按下面的宿主能力重新确定目标；工具调用成功不等于把焦点留在工具中运行生成动作也会成功。

## 动作怎样选择目标

| 目标方式 | 软件 | 运行要求 |
| --- | --- | --- |
| 前台进程精确路由（PID + 启动时间） | 3ds Max、AutoCAD、Blender、Cinema 4D、CorelDRAW、Maya、Revit、Rhino、SketchUp、SOLIDWORKS | 以触发时前台窗口对应的宿主进程定位；该实例未连接即失败，不回退到其他实例 |
| 前台窗口与组件精确路由（HWND + 组件） | WPS Office（预览） | 以触发时 WPS 窗口及文字/表格/演示组件定位；同窗口多组件时需明确组件 |
| 前台软件类型门禁 + 唯一在线会话 | Photoshop、Premiere Pro、After Effects | 触发时对应软件必须在前台，且只有一个在线 Bridge 会话；不保证按前台进程精确选择会话 |
| 唯一在线会话 | Illustrator、InDesign | 不按前台窗口定位；只允许一个在线 Bridge 会话 |

需要前台窗口的动作应从目标软件触发，例如使用配置好的快捷键或轮盘。触发之后切换前台，不会把记录的触发窗口换成新窗口。精确到进程不等于固定到文档：同一进程中的活动文档仍可能变化，具体以命令参数及宿主行为为准。

唯一会话模式遇到多个在线会话会拒绝执行，避免误操作。命令工具仍可显式选择会话用于诊断；要运行生成动作，应保存工作、关闭多余宿主或重复加载的 Bridge，刷新直到只剩一个会话。没有在线实例、前台软件不正确或目标不明确时，动作不会广播到全部实例。

## 结果、超时与错误

成功响应、命令排队和模型修改完成不是同一件事。尤其 AutoCAD 的部分命令/脚本通过命令队列执行，`queued: true` 只表示已排队，仍需在 AutoCAD 核对实际完成情况。

宿主有模态对话框、正在交互命令中或执行耗时任务时，可能暂时不能处理调用。先处理宿主提示，再检查结果。超时后不要立即重复发送修改命令，先核对是否已执行，以免重复修改。
