# 统一 AI 服务与模型设置

AI 设置集中管理服务连接、可用模型，以及各项功能按顺序使用的候选模型。先配置连接并验证所需能力，再为对话、文本处理或图像任务分配模型。

## 打开 AI 设置

服务连接在 **AI 服务** 中维护，各用途的候选模型在 **模型分配** 中设置。

打开 Quicker 设置，在“AI”分类中选择：

- **AI 服务**：管理服务地址、协议、凭据、代理、超时和可用模型；
- **模型分配**：为不同用途设置按顺序尝试的候选模型。

当前内置服务模板包括 OpenAI、DeepSeek、阿里云百炼、火山方舟、智谱 AI、Moonshot AI、MiniMax、百度千帆和硅基流动等。

也可以连接 Ollama、LM Studio 等本机服务，或填写兼容 OpenAI Chat Completions、OpenAI Responses 协议的自定义接口。

## 服务连接与模型分开管理

一个 AI 服务连接负责保存供应商、协议、API 地址、认证方式、代理和超时等信息。连接建立后，可以从服务获取模型列表，也可以手工填写 API 模型 ID。

模型可以单独启用、停用、测试和修改显示名称。Quicker 还会记录模型是否支持流式输出、工具调用、结构化输出和图片输入等能力。

能力状态用于帮助选择模型，并不能替代服务商的实际接口说明。自定义或新发布模型的能力可能显示为未知，可以在确认后手工调整。

助手允许选择 **工具调用能力未知** 的模型；明确不支持工具调用的模型仍不可选。可选不等于实际请求一定成功，建议先测试该模型的工具能力。连接中的模型旁可用 **分配** 选择用途，再到 **模型分配** 调整候选顺序。

## 服务商与模型分配 {/* #232--服务商与模型分配 */}

在 **设置 → AI** 中使用服务管理和「模型分配」两个入口；当前界面的服务管理页名为「AI 服务」：

1. 在 **AI 服务** 中添加连接，填写服务地址与凭据，检查连接；在同页管理该服务的模型，可「拉取模型」后加入，也可手动填写 API 模型 ID。
2. 确认模型启用及所需能力，再到 **模型分配** 为文本、图片或 Agent 等任务场景添加候选模型。
3. 在同一场景内拖动候选排序，或从候选的「⋯」菜单上移、下移、移除。优先顺序决定请求开始前选用哪个模型。

列表会说明模型被跳过的原因，例如连接停用、缺少密钥或所需能力未确认。**请求开始后发生错误，不会自动换下一个模型重试。** 应先检查错误、服务状态和配置，再重新发起。

在服务商页点击模型的能力标签，可探测支持情况，也可手动设为支持、不支持或恢复「自动（按目录判断）」。能力探测会真实调用服务，可能产生用量；探测失败不会直接判定为不支持。带 `*` 的能力表示用户修改过。

若候选只因所需能力未确认而不可用，菜单可提供「确认支持」。它等同手动把对应能力设为支持，**不是一次能力测试**；请先核对服务商说明或实际探测。明确不支持时不会提供这个快捷确认入口。

配置修改在切换页面或关闭设置时自动保存；候选顺序和能力状态仍应以保存后的界面为准。为某个模型选择「用此模型对话」只用于当前对话，不会改变任务场景的候选顺序。

## API 配置弹窗 {/* #237--api-配置弹窗 */}

已有连接、模型和用途配置会保留。可在 API 配置弹窗中检查服务和模型，再保存用于当前任务。

从 AI 对话的「配置 API」进入，可在弹窗中直接管理服务与模型，不必先跳到桌面设置页。桌面 **AI 服务** 页也可使用，两处读取同一套服务商与协议定义。

1. 点击「添加」，选择服务商，再核对地址、API Key 和协议；代理、超时等选项在「高级」中。
2. 点击「获取模型」并加入需要的模型，或「手动添加」准确的 API 模型 ID。添加服务只保存连接配置，**不会自动填入模板默认模型，也不会把首个连接加入 Agent 的模型分配**。
3. 点选列表中的模型作为诊断对象，按需执行「测试文本」「测试工具」「测试图像」。测试需要明确的模型和有效地址；空模型不会改用模板默认型号。测试会真实请求配置的服务，可能产生用量；文本通过不等于工具或图像能力通过。
4. 回到对话模型菜单，明确选择要使用的模型；需要改变按用途的候选顺序时，再到「模型分配」调整。**点选测试模型不会替当前对话换模型，也不会改写用途优先顺序**。

输入失焦、切换服务或点击「完成」关闭弹窗时会尝试保存。若校验或保存失败，当前编辑会保留并显示错误，先修正再完成；不能把关闭按钮等同于无条件保存成功。单纯选择测试模型不会触发配置保存。

## 先保存，稍后补全服务 {/* #incomplete-connections-2319 */}

添加服务后，可以先保存尚未填完整的连接，稍后继续配置。缺少密钥、地址无效、协议不支持等问题会在界面中提示；不可用连接及其模型不会作为正常候选参与调用，也不会阻挡其他已经配置正确的服务使用。

“已保存”不等于“可调用”。补全地址、凭据并添加模型后，按需检查连接并测试模型能力；实际请求仍可能产生用量。模型 ID 缺失、引用不存在的连接等配置结构问题，以及文件写入失败仍需修正，不能把所有错误都当作允许暂存的缺项。无法解析的自定义请求头、非整数超时会保留该字段原值并提示未保存，其他有效修改仍可保存。

回退 2.3.18 或更早版本后，未补全的服务可能使旧版无法保存 AI 设置；可先在新版补全或移除不用的服务，再回退。已有有效配置无需重新创建。

## 自动保存与密钥更换 {/* #235--自动保存与密钥更换 */}

离开编辑控件、切换服务商或页面、关闭设置时都会尝试自动保存。修改服务地址、模型或密钥后，可移开输入焦点提交，再使用「检查连接」核对结果；有无效输入或保存失败提示时，先修正，不能仅凭切换成功认定已保存。

已保存的 API Key 显示为「已配置」。点击「更换」后输入新密钥，保存成功后替换原密钥；在新密钥尚未保存时点击「取消更换」，可放弃本次输入。点击「清除」并保存成功会移除该服务的本机密钥；这不会到服务商撤销密钥。需要停用密钥时，还应到服务商处理。

## 按用途设置候选模型

V2 可以为日常文本处理与翻译、图片理解、Agent 与工具调用等用途设置候选模型顺序，也可以建立基于这些类型的自定义用途。

调用某项 AI 能力时，Quicker 会按照该用途的候选顺序寻找可用模型。连接被停用、凭据缺失或模型能力不符合要求时，该模型不会被当作正常候选使用。

“用此模型对话”可以直接测试当前模型，但不会修改用途的候选顺序。

## 思考档位与能力实测

模型设置展示该模型可用的思考档位；没有已知多档能力的模型不会凭空出现档位选择。不同供应商或协议支持范围可能不同，不能把一种模型的档位直接套用到另一种模型。

可分别测试文本、工具调用和图像能力。工具与图像测试结果用于更新模型能力状态；认证或网络失败不代表模型一定不支持该能力，应先排除连接问题再测试。模型测试会实际调用所配置服务，可能产生用量。

通过 OpenAI 兼容接口使用 Gemini 时，如果工具调用后的下一轮返回 HTTP 400，请先升级客户端再重试。仍失败时，按服务商返回信息排查认证、配额、模型名称和网络。

## 连接检查与推理档位 {/* #2310--连接检查与推理档位 */}

服务连接检查后，可继续选择发现的模型并配置用途，不必在密钥验证和模型配置之间反复切换。检查成功不等于模型已添加或已分配；仍需主动选择模型，并在对话菜单或 **模型分配** 中确认使用范围。检查或能力测试会请求服务，可能产生用量。

在模型编辑窗口的 **推理强度 → 可用推理档位** 中，可选择 **自动识别**，或按服务商实际支持情况 **手动选择**。手动勾选只调整 Quicker 提供的可选档位，不能让服务端支持原本不支持的参数；配置后请实际测试。

**默认推理强度** 只列出可用档位；其中的 **自动** 表示不发送推理强度参数，与明确选择 `none`（关闭思考）不同。助手对话仍保存自己的模型和档位，不会因修改模型默认值而统一替换所有历史对话的选择。

可用时，默认档位包括 **Off · 关闭思考**、**Min · 最少思考**、**Low · 低**、**Medium · 中**、**High · 高**、**Extra · 极高** 和 **Max · 最强**。Extra 与 Max 分别保存，界面只列出当前模型支持的选项；选「自动」也不保证服务端关闭思考。

模型默认值影响沿用该默认值的调用。若修改模型 ID 或可用档位后，原默认值已不可用，窗口会提示；保存后会恢复为自动，请在保存前核对。

### 为组合动作设置推理强度 {/* #action-reasoning */}

AI 文本处理、图片理解、文本分类、结构化提取和交互对话模块的高级参数中，可设置 **推理强度**；**AI 调用** 模块仅在使用 **全局 AI 配置** 时提供该参数。

| 选择 | 实际作用 |
| --- | --- |
| 跟随模型默认 | 使用实际选中模型的默认推理强度，适合统一管理 |
| 自动（不发送参数） | 本次调用不发送推理强度参数，即使模型配置了默认值 |
| Off、Min、Low 等明确档位 | 本次调用覆盖模型默认值，不会修改模型设置 |

明确档位必须由实际模型支持。Extra 与 Max 在模型缺少原档位时可映射到另一最高档；其它不支持的档位会让步骤失败，不会静默改用自动。更换候选模型或分享给其它设备前，先核对各模型支持范围，并用非敏感样例测试。

这些步骤参数要求运行设备使用 **2.3.50 或更新版本**；旧版可能忽略参数并按原默认值调用。回退或混用旧客户端前，请看[精确档位与旧版保存的兼容提醒](/v2/migration/upgrade-and-rollback#panel-and-reasoning-2350)。

回退旧版后保存 AI 设置，可能清除自定义可用推理档位。需要保留时先备份，重新升级后核对并重新设置，见[升级与回退](/v2/migration/upgrade-and-rollback#2310--ai-工作台与执行默认值)。

## 模型上下文上限 {/* #model-capacity-2332 */}

添加模型时，Quicker 会尝试读取服务商返回的上下文容量，也可按内置模型资料或已知模型名称识别。服务商未返回容量不等于模型不可用；如果新模型仍无法自动识别，会打开编辑窗口，要求填写 **模型上下文上限** 后再添加。获取服务端信息最多等待约 5 秒，失败后可手动填写。

在模型编辑窗口中，可从 **常见值** 选择上限，或输入整数、`128K`、`1M` 等值（K=1000，M=1000000）。请以当前服务商部署的模型说明为准，不能仅凭模型名称推断容量。手动填写的上限优先于自动识别值；服务地址或模型 ID 改变后，之前获取的容量不再适用。

**模型上下文上限** 表示模型可用容量；**Agent 工作上下文** 是助手实际使用的预算，受前者限制。调大设置不会扩大服务商的实际容量。

自动获取的容量记录随 AI 模型设置同步。混用旧客户端前请先备份 AI 配置，兼容边界见[升级与回退](/v2/migration/upgrade-and-rollback#model-capacity-and-sound-2332)。

## 响应超时 {/* #response-timeout-2327 */}

在 **设置 → AI → AI 服务** 页顶部，可以设置两项全局超时，范围均为 1–600 秒：

| 设置 | 什么时候生效 |
| --- | --- |
| 首次响应超时 | 流式请求开始后，等待首次输出的最长时间；非流式请求则用于等待完整结果 |
| 响应间隔超时 | 流式请求已开始输出后，等待下一次输出的最长时间；每次收到输出重新计时 |

持续输出的流式请求按首包与响应间隔超时判断；长对话的上下文压缩也按这两项规则等待。非流式请求不使用响应间隔超时。网络中断、服务商限流等错误仍需根据提示处理，增加超时不能修复这些原因。

首次升级时，缺失的首次响应设置沿用已有连接中最大的有效超时值，没有有效值时为 120 秒；响应间隔默认 60 秒。修改后确认保存成功再测试。

混用旧客户端或回退前，请先备份 AI 配置并查看[响应超时的兼容说明](/v2/migration/upgrade-and-rollback#ai-memory-and-timeout-2327)。

## 凭据如何保存

API Key 不会直接写入普通 AI 设置 JSON。Quicker 使用 Windows DPAPI，以当前 Windows 用户身份加密后保存到本机独立凭据文件。

因此，复制设置文件到另一台电脑或另一个 Windows 用户后，原凭据通常不能解密。需要在目标环境重新填写 API Key。

凭据不会写入动作定义，也不会随动作分享。调用远程服务时，输入内容仍会发送给所选服务商；费用、日志、数据保留和隐私政策由对应服务商决定。

## 在设备间同步 API 密钥

在 **设置 → AI → AI 服务** 页底部勾选「在设备间同步 API 密钥」；离开编辑控件、切换页面或关闭设置时会自动保存。开启后，AI 服务的 API Key 和自定义 Header 可随当前 Quicker 账号同步。该开关默认关闭，作用于 AI 服务配置整体，不是单个模型；离线账号不会上传。另一台设备需要登录同一账号，并使用支持此功能的版本。

**开启后凭据会上传到 Quicker 服务器，仅作基础混淆，不是端到端加密。** 服务端仍可还原，不适合把只允许本机保管的密钥放入此同步范围。它与本机的 Windows 凭据加密是两个不同边界，也不会把密钥放入分享的动作。

关闭并保存后，后续同步内容不再携带凭据；已经落到各设备的本机凭据不会因此自动清除，也不等于撤销服务商的密钥。需要撤销时，到对应服务商处理。若同步凭据无法解码，Quicker 保留当前设备已有的凭据；换设备后调用失败时，检查账号、服务配置和实际密钥，再运行能力测试。

**建议所有同步设备都升级到 2.3.1 或更高版本后再开启。** 旧客户端修改并同步 AI 设置，会清除凭据同步开关和云端的密钥字段；新版设备保留本机已有凭据，但需要重新开启同步。详见 [升级与回退](/v2/migration/upgrade-and-rollback#231-ai-数据按账号存放与密钥同步)。

## 在动作中使用 AI {/* #新增组合动作-ai-模块 */}

组合动作可以直接使用统一 AI 设置，不必在每个动作步骤中重复填写服务地址、模型和 API Key。以下模块用于处理并取得结果；另有[问问AI](/v2/xaction/modules/askai)用于打开助手并交付问题与材料，不等待回答：

- [AI 文本处理](/v2/xaction/modules/ai-text)：总结、改写、翻译、校对、改变语气，也可以使用完整系统提示词执行自定义任务；
- [AI 图片理解](/v2/xaction/modules/ai-vision)：识别图片内容、分析截图或按问题提取视觉信息；
- [AI 文本分类](/v2/xaction/modules/ai-classify)：从预先定义的分类中返回稳定 Key，便于连接条件判断和分支；
- [AI 结构化提取](/v2/xaction/modules/ai-extract)：按照 JSON Schema 从文本中提取对象和 JSON；
- [AI 交互对话](/v2/xaction/modules/ai-chat)：在流式对话窗口中继续追问，并由用户明确采用最终回答。

文本处理和图片理解既可以直接返回结果，也可以打开交互窗口调整回答。文本分类和结构化提取要求所选模型明确支持结构化输出；图片理解要求模型明确支持图片输入。

AI 交互对话会把会话保存在本机。动作分享不会携带会话历史，换设备后也不能使用原设备的会话 ID。每轮追问会根据当前任务场景重新选择可用模型；交互对话与对话测试可在输入区切换模型，也可添加图片及引用回复文字。含图请求需要支持图片输入的模型，详见[图片与后续追问](/v2/xaction/modules/ai-chat#images-2345)。

原有的 [AI 调用](/v2/xaction/modules/ai) 模块也可以把「模型来源」切换为全局 AI 配置，按任务场景使用候选模型，并支持把流式内容写入文本窗口。旧动作默认仍使用步骤内自定义 API，不会因升级自动改用全局凭据。

## 当前功能边界

的可选凭据同步范围见下方说明；复制普通设置 JSON 仍不能代替密钥同步或重新配置。

统一设置页提供公共的连接、模型和用途配置，但不表示所有历史 AI 入口已经在同一版本中完成迁移。具体功能是否使用这里的候选模型，应以该功能页面和实际界面为准。

Agent 对话和外部助手 MCP 设置已有用户入口，MCP 默认关闭；部分网页元素选择等能力仍受发布限制。设置页按分类组织。具体启用、写入权限和客户端同意步骤见 [AI 与 Agent 现状](/v2/features/ai-and-agent)。

配置正式动作前，建议先执行连接测试和模型测试，并使用不含敏感信息的样例确认协议、模型 ID 和能力设置正确。

使用 OpenCode 服务时，按服务商要求配置地址、协议和认证，再检查连接。Quicker 不提供该服务的订阅或使用额度。
