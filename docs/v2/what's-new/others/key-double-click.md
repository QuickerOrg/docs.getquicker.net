# 按键双击

按键双击可以在不拦截按键原有功能的情况下，监听同一个键连续按下两次并执行操作。例如双击 `Ctrl` 打开搜索，或双击 `Win` 运行一个常用动作。

2.x 保留了 1.x 的按键、说明、进程条件和自动退格等兼容数据，并把双击规则纳入统一场景管理。

## 为不同场景设置同一个双击键

可以在“场景与动作管理 → 键盘触发 → 按键双击”中，为程序、标题子场景和网址场景分别添加双击规则。

例如，双击 `F2` 可以在文件管理器中批量重命名，在编辑器中运行格式化动作，在其它程序中继续使用全局规则。

管理页默认只显示当前场景规则。开启“显示继承的规则”后，可以查看上级规则的真实来源，并将其复制到本场景再修改。

## 禁用本地规则时继续查找上级

按键双击沿用 1.x 的候选回退习惯，它和动作快捷键、文本指令的禁用语义不同：

- 本地规则启用且条件匹配：使用本地规则；
- 本地规则停用或进程条件不匹配：继续查找父场景和全局规则；
- 删除本地规则：同样会继续使用继承规则；
- 需要在某个场景完全避免触发继承规则时，不能只停用本地候选；应调整或移除相应上级规则。

这种行为保持了旧配置中“停用当前候选、继续尝试其它适用规则”的含义。

## Windows 键双击更稳定

双击左侧 `Win` 时，第一次按下通常会打开开始菜单并改变前台窗口。1.x 或早期 2.x 处理可能把这次前台变化当成场景变化，从而重置已经开始的双击判断。

现在，第一次按下时会保存当时匹配到的双击操作。只要第二次按下的是同一个键且仍在设定间隔内，就执行这次已选中的操作，不会因为按键自身打开开始菜单而丢失。

其它按键在两次按下之间引入新的受监视输入时，仍会重置待完成的双击，避免把不连续操作误判为双击。

## 管理和状态展示

新版列表会显示：

- 按键和用途说明；
- 操作类型与摘要；
- 规则来源；
- 引用动作失效或操作不可编辑等状态。

支持新增、双击编辑、启停、复制到本场景、多选和批量删除。按键本身不会被 Quicker 拦截，设置字母、方向键或其它常用输入键时，应先确认双击动作不会干扰目标软件。

## 从 1.x 升级时需要注意

- 原有按键双击规则会继续保留；
- 场景管理首要展示和编辑的是双击操作，旧数据中未在当前界面编辑的其它按键行为会保留；
- 停用本地规则可能继续触发继承规则，这是兼容行为；
- 使用左侧或右侧 `Win`、任务栏和开始菜单相关规则时，建议升级后重新测试；
- 浏览器网址场景会按当前网址、浏览器程序和全局链路查找规则。
